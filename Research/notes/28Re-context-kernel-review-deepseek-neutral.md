### 9. P3 proposes a gating axiom (lifecycle creator convergence licenses downstream elision) that the document states but never justifies
*severity: low* · *where: 28Q §3 ll.238–243* · *claim attacked:* "a CONVERGED creator elides, so its context is available at probe time, so entry-probing proceeds downstream" · *how it breaks:* The chain of reasoning is: (1) `useradd alice` at line 6 is a converged creator → (2) it elides at plan time → (3) but the user-alice context is still `arrives-at(6)` → (4) downstream probes enter the context. Step (1)→(2) is ordinary Dorc elision (converged → skip). But step (2)→(3) requires that elision preserves the availability fact: the create didn't RUN, but the context it would have created is still treated as available. This is a non-trivial theorem: elision normally means "the state already exists, so the command is no-op." But for a CREATE that elides, the state exists because it was converged *on a prior day*. On the current day, the create elides, and the context it would have created — which already existed — is available. The theorem holds for simple idempotent creators (user already exists), but the document presents it as a general law without examining its preconditions, edge cases (what if the creator's convergence check uses a different method than the downstream probe's entry check?), or interactions with the incarnation model (does a converged creator mint a fresh incarnation or reuse the existing one?). · *confidence: suspect*
