## §3 The re-weld deltas

### delta-1 · spike/CLAUDE.md — new "Standing human rulings (round-23)" block  [conductor applies on GO]

> - **rul-ternary-verdict.** The per-site verdict vocabulary is {elide, guard, run}. A `guard`
>   is an observable-preserving insertion — `<oracle-check-invocation> || <original bytes>` —
>   where the original command's bytes always survive verbatim (no code path removes them), and
>   the inserted code obeys ONE sourcing principle: *guard code is the oracle's own authored
>   body — the check IS the oracle — shipped strip-only (annotations removed, `name.check()` →
>   `name_check()`, nothing else changed; the strip's output is runnable sh), the same bytes
>   the probe lane ships under the structural self-vouch.* Whole-body shipping is the default;
>   a lifted/deconstructed form is an OPTIONAL analyzer edge-case, and even then must be
>   byte-identical to a *substring* of the oracle body — sh's own control-flow performs
>   path-selection at runtime anyway (the site's argv reaches only its own path), so lifting
>   buys bytes and readability, never different behaviour. Two nevers, spelled so they can't
>   erode: never engine-synthesized sh (no author, no self-vouch, no attribution — and a second
>   source of convergence-truth that could disagree with the probe); never declared/claimed
>   output in guard-position (testimony may inform licensing but never becomes code or output
>   there — printing an un-run tool's message manufactures evidence of a run that didn't
>   happen; the INVERSE case — reproducing values for a fully-ELIDED command's consumers — is
>   the existing probe-provenance stand-in machinery, governed by inv-probe-sourced-values, and
>   is untouched). Signing this delta IS the supersession of the round-21 door-4 deferral
>   ("flag-gated, default `Never`, builds last, product hard-defers") — the reversal 233's
>   update flagged as to-be-re-welded consciously; it happens here, by this GO, not by any
>   earlier decision.
> - **rul-guard-license.** A guard mints only from a matching (call-site, reached
>   converged-vouch, probe-verdict) witness. The vouch is a mark on a path through the oracle's
>   own check-body, scoped by constant-propagation reachability; it NEVER enters the fact-plane
>   and is inadmissible in any other site's elide/poison reasoning. Run-delta verbs never guard
>   (an oracle declines by not vouching). No vouch ⇒ run. Spelling of the vouch is OPEN; build
>   against a stub marked strawman.
> - **rul-attention-honesty (welded).** Attention is saved ONLY by provable elision. The plan
>   render is the whole book in original order; lines that will execute are never hidden or
>   folded (at most dimmed, warily). "Scrappy, but correct: never hide risk from the user."
> - **rul-divergence-proceed.** Apply-time divergence from plan prediction: proceed-and-flag;
>   no abort, no strict mode. All decisions front-load into the single approval; late events are
>   report-items only (the attention-chronology doctrine). The engine adds no second-guess layer
>   above guards; defensive surfacing of broken world-state is the oracle's job on its own
>   channels.

*Rationale engaged (door-4's deferral reasons, not just its letter):* the deferral rested on the
trust-boundary taxonomy ("a bad oracle must never cause novel apply-phase actions") and
correlated-failure worry. The re-weld answers them rather than waiving them: apply-lane oracle
code is bounded to the SAME trust-object the probe lane already ships — the stripped oracle body
under the structural self-vouch; same bytes, both lanes, no new code-class crosses the
boundary; each insertion is licensed by an
explicit, attributed, per-verb human claim rather than ambient analysis; every guarded site is
disclosed in the plan; and the posture-shift was adversarially crosschecked (236a/b/c, adjudicated
in 237) before adoption. The correlated-failure residue (a lying probe body misleads at plan AND
acts at apply) is real, named, and identical in kind to the residue HEAD already carries for
plain elision — narrowed, if anything, by the guard's fall-through-to-run default.

*Candidate invariant surfaced in review (human, 2026-07-02 — flagged, NOT part of this GO;
"bears more thought"):* **one-body-two-lanes** — probe-time and apply-time-as-guard ship the
byte-exact same function bodies, so guard behaviour can never drift from probed behaviour, and
every probe run actively exercises the guard's code. Costs he named: without manipulation,
apply artifacts balloon (render-mitigation candidate: show runbook lines + topology, oracle
bodies on demand); with manipulation (the thin pole), the extracted residue must be derived AT
probe time, named, and shipped there too — "tested in the probe so it can be trusted at apply."
Tensions with apply-guard-thin by construction; nearly free at the fat pole. Routed to task #2;
if later welded, a byte-identity xfail pin follows. *(Same-day stream-uncrossing: under the
human's ground-truth — whole-oracle body ships in both lanes — this is nearly AUTOMATIC; it
remains a live constraint only for the optional lifted-subset form, where the shipped substring
must also have shipped and been exercised at probe time to qualify.)*

### delta-3 · spike/CLAUDE.md — carve-out clause on inv-probe-sourced-values  [conductor applies on GO]

> Guard-insertion is NOT a Replace and mints no values: a GuardInsert carries no StandIn, no
> Predicted, no Observable — a guard reproduces nothing (on pass, the probe's own live rc is the
> line's rc; on fall-through, the original command executes and its observables are genuine).

fancy stand-in") unspellable.
