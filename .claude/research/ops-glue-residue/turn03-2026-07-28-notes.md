## Findings

### The single highest-value structural finding

- **A controller-side wait-loop is an O(retries) connection generator, and that is the exact cost
  cdist named as its own stated regret.** Every iteration of `until ssh …; do sleep; done` is a
  fresh TCP+auth handshake. `[A-nixos-anywhere-main-script-2026]` runs four such loops in one
  invocation, each spawning one ssh per second; `[C-awayto-multihost-deploy-glue-2024]` runs two
  per host across seven hosts. Against `[A-cdist-manual-best-practice-connection-cost-2026]`
  (connection count is the incumbent's regret) and `[B-radman-minimalist-scripted-configuration-2021]`
  ("performance degrades with each module"), the consequence is sharp and, I believe, new:
  **an in-artifact wait costs one connection total; a controller-side wait costs one per poll.**
  Dorc's one-artifact-per-phase differentiator therefore argues for *compiling waits into the
  artifact* wherever the wait is for something the target can observe. It only argues the other way
  for the pivot's own wait — waiting for a host to become reachable is definitionally not
  observable from inside that host. +SURE on the mechanism; -0:SUSPECT that this is the right
  design cut rather than merely a true observation. DESIGN-BEND: yes, and it cuts across
  `dir-until-loop-glue-priority` and the pivot requirement simultaneously.

### Q1 — wait-loop reality

- **Wait-loops are dense, and they are not one idiom but five, of which Dorc's analyzer walls all
  five identically.** The shapes actually found, in rough descending order of index frequency (see
  the frequency note below): `while ! <probe>; do sleep N; done` · `until <probe>; do sleep N; done`
  · `until <probe>; do sleep N; done` wrapped in `timeout T bash -c "…"` · `for i in <range>; do …
  break … sleep; done` (a retry *cap*) · `while :; do <probe>; [ rc = 0 ] && break; sleep; done`
  (`[A-wait-for-it-script-2020]`). +SURE.
- **The probe inside the loop is almost never the thing you actually need, and one specimen says
  so out loud.** `[B-kthw-vm-ssh-setup-pivot-2026]` runs *two* loops with different predicates and
  comments the difference: `until nc -zw 10 "$vmname" 22` ("ready to accept SSH connections") then,
  after keyscanning, `until ssh "ubuntu@$vmname" exit` ("boots up and starts accepting
  **unprivileged** SSH connections"). Port-open is not login-works. This is
  `ack-connection-dance-oracles-core`'s rider (reachable≠provisioned) observed in the wild, by an
  author who hit it. +SURE.
- **Mature tools ship first-party wait VERBS, and the loop appears exactly where they don't.**
  `pg_ctl -w` in `[A-postgres-docker-entrypoint-2026]`; `waitFor` in
  `[A-devcontainer-lifecycle-scripts-2026]`; helm's "waits until the hook is Ready" and `--wait` in
  `[A-helm-chart-hooks-2026]`; the `Wait for connection` handler with a 300s default in
  `[A-ansible-community-openwrt-user-guide-2026]`. Corollary worth keeping: the reference
  docker-entrypoint contains **no** readiness loop at all — the wait-for-it genre exists to patch
  images that lack a wait verb, not because entrypoints are inherently loop-shaped. ~SUSPECT on
  the generalisation, +SURE on the four instances.
- **cloud-init's readiness answer is eight-valued, and separates "degraded done" from "done"**
  `[A-cloudinit-status-states-2026]`. An incumbent shipping the wrong-but-not-broken cell as a
  first-class readiness state. Bears directly on any Dorc readiness fact being boolean.
- **Two canonical retry caps in the corpus of famous scripts are silently broken on the POSIX
  floor.** `[A-k3s-install-script-2026]` (a `#!/bin/sh` script that explicitly supports Alpine via
  its openrc branch) writes `for i in {1..3}; do … sleep 1; done`; the Kubernetes documentation's
  own suggested init-container one-liner `[A-k8s-init-containers-docs-2026]` writes
  `for i in {1..100}; do sleep 1; if nslookup myservice; then exit 0; fi; done; exit 1` against a
  `busybox:1.28` example image. Brace ranges are not POSIX `[A-posix-2024-shell-language-2024]`.
  VERIFIED LOCALLY this turn (`/bin/dash -c 'for i in {1..3}; do …'` → one iteration, `i` literally
  `{1..3}`): the k3s retry retries zero times, and the documented 100-second k8s wait waits one
  second and then exits 1. +SURE for dash/posh; ~SUSPECT for every busybox build.
  DESIGN-BEND: this is a **diagnostic** payoff that needs no elision machinery — recognising
  bounded-retry shapes lets Dorc say "this loop does not loop". That is warning-tier value in the
  band the boilerplate-cargocult razor says to tune high during spike.
- The dpkg-lock `fuser` idiom that turn A found canonical is dense enough to be unmissable
  (GitHub index, literal `"fuser /var/lib/dpkg/lock" language:shell`: 1,976 files), corroborating
  `[B-sinjakli-apt-lock-timeout-2021]` and `[A-cloudinit-aptdaily-lock-race-2017]` at scale.

### Q2 — inline-ssh multi-host sequencing

- **The median multi-host glue script is a sequence of `ssh host <<EOF` heredocs with local
  variable interpolation, and that is simultaneously the env-marshalling answer and the
  env-marshalling bug.** `[C-awayto-multihost-deploy-glue-2024]` ships two unquoted heredocs to two
  different hosts in one file; `$DB_VERSION`, `$BUILD_HOST` and `$PG_PASS` all expand on the
  controller. It works, it is readable, and it has no boundary marking which side evaluates what.
  +SURE.
- **The same file is a live instance of turn B's stdin-consumption escalation.** `ssh -T host <<EOF`
  feeds the remote login shell its script on fd 0, and the interior runs `sudo` repeatedly — a
  password prompt would eat script bytes. This is the hazard `ack-stdin-hygiene-banked-aside`
  banked, found unprompted in real code. +SURE on the shape; ~SUSPECT that it bites in practice
  here (NOPASSWD is likely).
- **Quoting pain is not confined to scrappy scripts; the top-tier tool documents it in comments.**
  `[A-nixos-anywhere-main-script-2026]` carries a three-line comment explaining `"${nixOptions[@]@Q}"`
  ("otherwise SSH will drop the quotes"), uses `printf '%q'` for another argument, and links out to
  the folklore. `[A-k3s-install-script-2026]` hand-rolls `quote()`/`quote_indent()`/`escape()`/
  `escape_dq()` — four sed-based quoting helpers — in a *single-host* installer. This is the fifth
  and sixth independent rediscovery on top of turn B's cdist/judo/remotely trio. +SURE.
- **Terraform states the copy-then-exec rationale first-party, and the reason is state continuity,
  not performance:** provisioners "upload the script file to the remote system then use the default
  shell to execute it … because it allows you to use all of the typical scripting techniques
  supported by that shell, including preserving environment variable values and other context
  between script statements" `[A-terraform-provisioners-remote-exec-2026]`. That makes five members
  of the copy-then-exec family (cdist/judo/drist/remotely + terraform) against rset's lone pipe,
  and it is the clearest available argument for one-artifact-per-phase. +SURE.
- **The controller/target evaluation split is stated as an incumbent limitation:** provisioners
  "cannot react directly to remote environment variables, such as `TMPDIR`, or use functions such
  as `mktemp` because they run on the system where Terraform is running, not on the remote system"
  — hence the `script_path = /tmp/terraform_%RAND%.sh` convention
  `[A-terraform-provisioners-remote-exec-2026]`. Read against `delegate_facts`
  `[A-ansible-delegation-docs-2026]` and DeHaan `[A-dehaan-pull-mode-announcement-2012]`: this is a
  third incumbent hitting the attribution/scope-typing wall from a third direction. Note the
  asymmetry it implies **in Dorc's favour**: a ship-one-artifact model lets the *host's own*
  `mktemp -d` + `trap` do the work, which is exactly what `[A-k3s-install-script-2026]` does.
  +SURE.
- Ordinal frequency for the shape itself: literal `"for host in" "ssh " language:shell` → 5,656
  indexed files. The canonical body is one unquoted `ssh $host "…$var…"`.

### Q3 — branch-on-facts

- **Branch-on-facts is denser than wait-loops by roughly an order of magnitude and is the
  single most common non-trivial construct in the specimen class.** Ordinal index counts:
  `". /etc/os-release"` → 28,256 files; `"case \"$(uname"` → 28,416. Both dwarf every wait-loop
  query run. +SURE that the ordering is real; the absolute numbers are index artefacts, see the
  frequency caveat.
- **The idiom has exactly four recurring shapes**, all present in
  `[A-tailscale-installer-script-2026]` and `[A-k3s-install-script-2026]`:
  (i) source-and-case — `. /etc/os-release` then `case "$ID" in …` (tailscale's has ~50 arms across
  ID values, several of which `exit 1` with human instructions rather than installing);
  (ii) uname fallback — `case "$(uname)" in FreeBSD|OpenBSD|Darwin|Linux)` used *only* when
  os-release was absent;
  (iii) command-presence — `type curl >/dev/null; elif type wget`, `[ -x "$(command -v $1)" ]`;
  (iv) filesystem-existence-as-inference — `[ -x /sbin/openrc-run ]`, `[ -d /etc/zypp/repos.d ]`,
  `[ -r /etc/redhat-release ]`, `[ -d /usr/share/selinux ]`. +SURE.
- **A fifth shape matters more than its frequency suggests: probe-the-behaviour, not the name.**
  `[A-nixos-anywhere-get-facts-2026]` sets `hasSetsid` only if `setsid --wait true` actually
  succeeds, because the binary exists on busybox without the flag; `[A-wait-for-it-script-2020]`
  runs `timeout` and greps its own usage output for `-t ` because recent Alpine dropped the flag;
  `[A-tailscale-installer-script-2026]` probes for `dnf-command(config-manager)` and falls back to
  `dnf-3` because **DNF 5 shipped without a feature DNF 3 had**. +SURE.
- **A hand-rolled probe PHASE exists in the wild and looks exactly like Dorc's.**
  `[A-nixos-anywhere-get-facts-2026]` is twenty lines of POSIX sh shipped on stdin to `sh --` in a
  single connection, emitting one heredoc of `key=value` facts, which the controller then filters
  with `grep -E '^(has|is|remote)[A-Za-z0-9_]+=\S+'` and `export`s
  `[A-nixos-anywhere-main-script-2026]`. Fourteen facts, all independent booleans or scalars. This
  is probe/plan/apply's probe phase, one-artifact-one-connection, written by hand because no tool
  offered it. +SURE. Strongest single validation this turn.
- **The privilege trichotomy is a fact, and three independent tools compute it identically:**
  root / `sudo` / `doas`, collapsing to a `$SUDO` or `$maybeSudo` prefix variable
  (`[A-tailscale-installer-script-2026]`, `[A-nixos-anywhere-main-script-2026]`;
  `[A-k3s-install-script-2026]` does the two-way version). It is always computed once at the top
  and threaded through every later line as a variable expansion. DESIGN-BEND: this is the shape the
  open sudo/privilege gap will have to model — not a per-line escalation decision but a
  single early-bound host fact that prefixes most mutating lines. +SURE on the observation.
- **`command -v <tool>` guards and content-guards are the idempotence idiom, exactly as Dorc's
  README assumes.** `if ! command -v docker >/dev/null 2>&1; then …install… fi`
  `[C-awayto-multihost-deploy-glue-2024]`; `if ! command grep -qc '/nvm.sh' "$NVM_PROFILE"; then …
  >> …` `[A-nvm-install-script-2026]`; `SELECT 1 FROM pg_database WHERE datname = :'db'` then
  create-if-empty `[A-postgres-docker-entrypoint-2026]`; `if [ -s "$PGDATA/PG_VERSION" ]` as a
  first-run marker. The last two are oracle-shaped: ask the tool for state, then act. +SURE.

### Q4 — dorc-inside seats: the headliner is answered, in Kubernetes' own words

- **k8s-native machinery provably does NOT reach script content, and the doc says both halves.**
  Conjunct (a): "If the Pod restarts, or is restarted, all init containers must execute again."
  Conjunct (b): "Because init containers can be restarted, retried, or re-executed, init container
  code should be idempotent." And the kill-path is *structurally* foreclosed: "Kubernetes prohibits
  `readinessProbe` from being used because init containers cannot define readiness distinct from
  completion. **This is enforced during validation.**" `[A-k8s-init-containers-docs-2026]`.
  Probes govern workload health; at the seat where setup scripts live they are a validation error.
  +SURE. This is the round's cleanest survive verdict.
- **"Mandate idempotence by doc, assist none of it" is now a six-member pattern, not a chezmoi
  quirk.** Corpus already had chezmoi/yadm/dotbot/home-manager (24R §1c). Add: Kubernetes init
  containers (above); Terraform destroy-time provisioners — "You should ensure that the
  destroy-time provisioners are safe to run multiple times"
  `[A-terraform-provisioners-remote-exec-2026]`; devcontainers — "The command may run more than
  once during a given session" `[A-devcontainer-lifecycle-scripts-2026]`. +SURE. The escape-hatch
  discriminator is not merely corpus-confirmed, it is the ecosystem norm.
- **Three unrelated systems have independently invented a tri-state "I found nothing to do" exit
  convention, and none of them agree on the encoding.** systemd `ExecCondition=`: 0 proceed,
  1–254 skip-without-failing, 255/abnormal fail `[A-systemd-service-exec-directives-2026]`. GCP OS
  Policy: 100 in-desired-state, 101 not, exiting 0 is an *error*
  `[A-gcp-os-policy-proto-googleapis-2026]`. Radman's `rinstall(1)`: "Exit `0` only if file was
  installed **or changed**" `[B-radman-minimalist-scripted-configuration-2021]`. DESIGN-BEND: the
  missing primitive these three are each groping for is precisely what a Dorc oracle reports. That
  convergence is a strong, citable argument that the oracle rc contract is filling a real hole
  rather than inventing one. +SURE on the three encodings; -0:SUSPECT on the "same hole" reading.
- **systemd's assistance is real but strictly unit-granular**, which is what keeps the seat alive
  at line granularity: `Condition…=` prevents activation entirely, `ExecCondition=` skips the whole
  chain, a `-` prefix ignores one command's rc, `Restart=`/`RestartSteps=` handle retry and
  backoff. Nothing looks at state *inside* a prep script. And `ExecStartPre=` re-runs on every
  start, with restart defined as stop-then-start `[A-systemd-service-exec-directives-2026]`. +SURE.
- **Terraform's seat is alive only in the pattern HashiCorp is actively trying to kill.**
  `terraform_data` + `triggers_replace` re-runs on *replacement*, which normally means a fresh
  machine (conjunct (a) fails). It survives only in the `triggers = { … }`-against-a-long-lived-host
  abuse, and Terraform disclaims the whole area ("Terraform cannot predictably model provisioner
  behaviors"; "you should exhaust all alternatives"). By the charter's own reformulation — real
  seats are disclaimed escape hatches — that is a *pass*, which is uncomfortable and worth the
  human's attention. ~SUSPECT.

### Q5 — pivot pain: the identity question is settled, and the answer is "everyone gives up"

- **Two independent reference tools disable SSH host-key verification outright because the target
  is newly created.** nixos-anywhere hardcodes `-o UserKnownHostsFile=/dev/null -o
  StrictHostKeyChecking=no` `[A-nixos-anywhere-main-script-2026]`; Terraform: "Because the SSH
  connection type is most often used with newly-created remote resources, SSH host key validation
  is disabled by default" `[A-terraform-provisioners-remote-exec-2026]`. The hand-rolled specimens
  do the manual equivalent: delete stale known_hosts lines, then `ssh-keyscan >> known_hosts`
  `[B-kthw-vm-ssh-setup-pivot-2026]`, `[C-awayto-multihost-deploy-glue-2024]`. +SURE. The ~SUSPECT
  in the charter's seed is CONFIRMED and stronger than suspected: identity churn is not an edge
  case of the pivot, it is the defining property, and the universal answer is to stop verifying.
- **Facts do not survive the pivot, and the tool re-gathers them.** `runKexec()` ends by calling
  `importFacts` a second time and then asserting `isInstaller == y`
  `[A-nixos-anywhere-main-script-2026]`. DESIGN-BEND, and a sharp one: a pivot **invalidates every
  host-scoped fact**, including any connection fact an `ssh` oracle minted before it. Scope-typing
  needs not just "which host" but "which epoch of that host". +SURE that the tool does this;
  -0:SUSPECT that epoch-typing is the right Dorc framing rather than just re-probing.
- **The pivot needs a wait-loop in the INVERSE direction, which nothing in the corpus models:**
  `while runSshTimeout -- exit 0; do sleep 1; done` — wait for the machine to become *unreachable*
  — appears twice (after kexec, after reboot), each followed by an `until … reachable` loop
  `[A-nixos-anywhere-main-script-2026]`. A reboot-shaped pivot is wait-gone → wait-back → re-probe,
  three phases, not one. +SURE.
- **Across a pivot the channel rc is worthless and the tool substitutes an in-band sentinel.**
  "The script will likely disconnect us, so we consider it successful if we see the kexec message":
  the remote block tees to a log, `|| true` swallows the rc, and success is decided by
  `grep -q 'machine will boot into nixos'` on that log
  `[A-nixos-anywhere-main-script-2026]`. This is `26A` stop-2's doctrine, arrived at independently,
  for the case that forces it. Best available external validation of never-trust-channel-rc. +SURE.
- **The pivot's remote script is materialised to a file before execution, not piped** —
  `runSsh 'mkdir -p "$HOME/kexec" && cat > "$HOME/kexec/…kexec.sh"' <<EOF` then
  `runSsh 'bash "$HOME/kexec/…kexec.sh"'` — the same `cat - >tmp && exec sh tmp` shape turn B
  identified as the stdin-hazard fix in `[A-johnkaul-drist-shell-reimplementation-2025]`, now with
  a top-tier adopter (though split across two connections, and the same tool still uses
  `runSsh sh <<SSH` elsewhere). +SURE.
- **The network-reconfiguring cousin of the pivot is shipped by an incumbent:**
  `[A-ansible-community-openwrt-user-guide-2026]` ships a `Wait for connection` handler with
  `openwrt_wait_for_connection_timeout` defaulting to 300s, for "after a network or wifi restart" —
  i.e. after the book changed the transport out from under itself. +SURE.

### Q6 — heterogeneous-fleet capability non-monotonicity

- **The strongest evidence is not practitioner anecdote but a maintained collection whose entire
  existence is the non-monotonicity.** `[A-ansible-community-openwrt-user-guide-2026]`: "some
  devices have limitations of resources, preventing Python from being installed"; "The modules in
  this collection are all written in shell script (more specifically `ash`)"; `gather_facts=true`
  "will **always** try to run Python in the target node", so it must be globally disabled and
  re-enabled **per host** via `openwrt_gather_facts: true` in `host_vars`, with all other hosts
  falling "through to `ansible.builtin.gather_facts` unchanged." A single inventory where one
  member's capability set forces a per-host branch in the control plane. +SURE.
- **Per-FEATURE, not per-tier, is what the same collection actually needs:** `coreutils-sha1sum`
  "required for any module that uses/provides SHA1 hashes", `coreutils-base64` for base64
  manipulation, plus `openwrt_scp_if_ssh` with a *three*-valued `true`/`false`/`smart` because
  scp-vs-sftp availability varies. Feature → min-capability, exactly as
  `rul-capability-probing-per-feature` states. +SURE.
- **Newer is not more capable — three instances:** DNF 5 lacking DNF 3's `config-manager`
  `[A-tailscale-installer-script-2026]`; busybox `setsid` present but without `--wait`
  `[A-nixos-anywhere-get-facts-2026]`; Alpine's `timeout` dropping `-t`
  `[A-wait-for-it-script-2020]`. No version ladder sorts these. +SURE. Taken with the
  init-system spread (systemd / openrc / FreeBSD `service` / App Store / refuse-and-instruct in
  `[A-tailscale-installer-script-2026]` and `[A-k3s-install-script-2026]`), the ruling's
  feature-detection-not-user-agent-sniffing analogy is empirically the right one.
- Honest limit: I found no source that inventories *one person's* mixed fleet spanning busybox NAS
  + Debian + macOS + router. The evidence above is capability non-monotonicity within tool and
  distro space, which is the same phenomenon one layer down, plus one shipping collection that
  proves a mixed inventory needs per-host control-plane branching. -0:SUSPECT that this is
  sufficient grounding for the human's ruling; it does not *prove* the homelab-shaped claim.

### Radman's enumerated failures, tested against the specimens (not re-derived)

His list for `ssh 10.5.5.1 < configure-wordpress.sh` `[B-radman-minimalist-scripted-configuration-2021]`:

- ✗ **"Install configuration files" — PARTLY REFUTED.** Every specimen installs config files fine,
  with `tee <<EOF`: `[A-k3s-install-script-2026]` writes five files that way (unit, env, repo,
  killall, uninstall); `[C-awayto-multihost-deploy-glue-2024]` writes `/etc/docker/daemon.json` by
  `echo | sudo tee`; `[A-nixos-anywhere-main-script-2026]` uses `cat >` over ssh. What is *actually*
  missing is his third bullet, not this one.
- ✗ **"No exit code indicating if the file changed" — CONFIRMED, and it is the real gap.** Not one
  specimen can tell whether a `tee`-written file changed. `[A-k3s-install-script-2026]` works around
  it with a bespoke `PRE_INSTALL_HASHES` / `POST_INSTALL_HASHES` sha256 comparison to decide
  whether to restart ("No change detected so skipping service start"). That is `rinstall`'s
  convention, hand-rolled, in a first-tier installer. +SURE. DESIGN-BEND: this is exactly Dorc's
  `# converged: content match` line, and the evidence says people build it themselves when they
  need it.
- ✗ **"Apply part of a config" — CONFIRMED, strongly, with the cost visible.** Three independent
  hand-rolled partial-application mechanisms: k3s's ~20 `INSTALL_K3S_SKIP_*` / `_FORCE_` env knobs
  `[A-k3s-install-script-2026]`; nixos-anywhere's `--phases kexec,disko,install,reboot` with a
  `declare -A phases` map, which visibly *replaced* two earlier ad-hoc flags now marked deprecated
  (`--stop-after-disko`, `--no-reboot`) `[A-nixos-anywhere-main-script-2026]`; rset's Progressive
  Label Notation `[B-radman-minimalist-scripted-configuration-2021]`. +SURE. Dorc's probe/plan gives
  this by *state* rather than by hand-declared phase flags — the clearest value claim of the turn.
- ✗ **"No convention for transferring files to a staging directory" — REFUTED for the
  ship-one-artifact form.** `TMP_DIR=$(mktemp -d …)` + `trap cleanup INT EXIT`
  `[A-k3s-install-script-2026]` works precisely because the script runs on the target. Terraform,
  which orchestrates from outside, must name the remote path blind and invented
  `%RAND%` `[A-terraform-provisioners-remote-exec-2026]`. The failure is controller-side, not
  artifact-side. +SURE.
- ✗ **"Performance degrades with each module" — CONFIRMED and extended** — see the connection-count
  finding at the top; wait-loops amplify it beyond what he measured.
- > **"'curl' in everything you want" — CONFIRMED as the norm.** k3s curls its binary; tailscale
  curls keys and repo files; awayto runs `curl … get.docker.com | sh` *nested inside* an ssh
  heredoc; nixos-anywhere probes `hasWget`/`hasCurl` and only falls back to piping from the
  controller if neither exists. That last is turn B's "synthesize the capability out-of-band"
  (`[A-ansible-aws-ssm-connection-2026]`) at the sh tier. DESIGN-BEND: the real-world norm assumes
  **target-side egress**, which turn A's self-contained offline artifact deliberately does not.
  +SURE.

### One unrelated finding worth keeping: the partial-download hygiene wrapper

Three independent canonical installers wrap their entire body so a truncated download cannot
execute half a script, and one states the rationale in a comment:
"All the code is wrapped in a main function that gets called at the bottom of the file, so that a
truncated partial download doesn't end up executing half a script"
`[A-tailscale-installer-script-2026]`; `{ # this ensures the entire script is downloaded #`
`[A-nvm-install-script-2026]`; k3s's trailing `{ verify_system; setup_env "$@"; … }` block
`[A-k3s-install-script-2026]`. +SURE. DESIGN-BEND: this is the "hygiene wrapper" constraint
`ack-splice-floor-framing` already lists, now with three first-party precedents and a stated
rationale — it is a *known idiom* to reuse, not a Dorc invention to justify.

## Threads for turn D (cdist/pyinfra featureset comparison)

- **Radman already drew Dorc's box, in 2021, and called it pyinfra's.** His "Two-Stage Model" is
  "1. Execute remote scripts return information 2. Generate shell scripts 3. Execute scripts on
  remote host / ✓ No remote dependencies ✓ Easy to debug ✓ Reasonably easy to extend ✓ Fast
  ✓ Multiple transports, not just SSH / ✗ Python only"
  `[B-radman-minimalist-scripted-configuration-2021]`. Every ✓ is a Dorc claim; the sole ✗ is the
  authoring language. Turn D should start from the position that **Dorc is pyinfra's architecture
  with the authoring language changed**, and hunt for what else differs, rather than assembling a
  comparison from scratch. Combined with `_if=` `[A-pyinfra-deploy-process-2026]` (turn B), pyinfra
  is the closest prior art on two axes at once.
- Radman's taxonomy gives turn D a ready frame for the whole field: Agent-Server (chef/puppet/salt)
  · Gather-Fact (ansible/salt-ssh) · Two-Stage (pyinfra) · Remote Execution (rset/drist/judo), each
  with his own ✓/✗ columns.
- His per-model "what does it buy you" asides are candidate raw material for the honest
  "if you're doing X, go use Y" README advice the charter wants — e.g. for the agent-server model,
  "Central status of systems (reporting) · One place of authority · Auditing · Windows".
- The three tri-state rc conventions (systemd / GCP / rinstall) belong in turn D's comparison as a
  featureset row: nobody has a portable "nothing to do" signal, and every tool invents one.
