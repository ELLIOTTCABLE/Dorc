# turn 1 — 2026-07-28 07:46:00 CDT

Scope: pre-SSH lifecycle channels, and the feasibility/constraints of an offline compiled-guard
artifact (`dorc compile book.sh > payload.sh`). Eight questions; breadth over depth.

## Findings

- The hypothesis's channel claim survives; its **novelty** claim needs restating. A plain-sh
  every-boot user-data channel already exists in the dominant incumbent: `#cloud-boothook`
  [A-cloudinit-boothook-format-2026]. What does *not* exist is convergence machinery for it —
  upstream's own once-per-instance example is a hand-written guard.
- Upstream cloud-init **disclaims** re-running its own payload: "may be destructive and must never
  be done on a production system", framed purely as debugging [A-cloudinit-rerun-howto-2026]. The
  cell is not merely unoccupied — the incumbent has actively vacated it.
- "EC2 ~16KB" is **true and primary**: 16 KB raw, pre-base64 [A-aws-ec2-user-data-2026]. But it is
  the *tightest* mainstream cap by an order of magnitude — GCP allows 256 KB
  [A-gcp-startup-scripts-linux-2026], Azure 64 KB [A-azure-custom-data-2026], DigitalOcean 64 KiB.
  Sizing a compiled artifact against 16 KB is sizing against the worst cell, not the median.
- GCP is the counter-example cloud: `startup-script` runs on **every boot**, not once, and is
  manually re-runnable (`google_metadata_script_runner startup`) [A-gcp-startup-scripts-linux-2026].
  A GCP startup-script is already, semantically, a day-N convergence artifact with no convergence.
- Ignition/Talos are **not the same boundary**. Talos is genuinely conceded: no shell, no SSH, no
  busybox, at all [A-talos-philosophy-2026]. Ignition is *awkward*, not closed: maintainers'
  sanctioned pattern is a written file plus a one-shot `ConditionFirstBoot=true` systemd unit that
  "can run whatever commands you want" [A-ignition-issue-909-shell-2020].
- Ignition's rationale states the exact negation of artifact-unification as a design axiom:
  "Ignition runs only on the first boot… machine modification requires that users discard the old
  node and re-provision" [A-ignition-rationale-2026].
- Installer hooks are a *better* fit than cloud user-data, not worse: subiquity's own documented
  example is download-a-script-and-`/bin/sh`-it [A-subiquity-autoinstall-reference-2026]; preseed
  ships `preseed/run` which downloads a program and runs it [A-debian-preseed-custom-commands-2025].
  Both execute in a **busybox** installer environment [A-debian-installer-internals-2024], so the
  dialect floor question (Q6) is load-bearing here, not academic.
- Packer's shell provisioner is literally upload-one-file-and-exec:
  `chmod +x {{.Path}}; {{.Vars}} {{.Path}}`, default shebang `/bin/sh -e`
  [A-packer-shell-provisioner-2026]. Zero adaptation needed for a compiled artifact.
- The Q8 pain is real, long-lived, and **guard-shaped**: apt-daily racing cloud-init's own apt
  invocation, unfixed at the apt layer for years [A-cloudinit-aptdaily-lock-race-2017], with the
  community's answer being hand-rolled `while fuser /var/lib/dpkg/lock-frontend; do sleep 1; done`
  loops — 271 askubuntu hits for one query [B-sinjakli-apt-lock-timeout-2021].
- Secrets hazard, unprompted but design-bending: on EC2 the payload is an *instance attribute*
  readable back through IMDS, and Azure draws the line explicitly — custom-data is NOT in IMDS,
  user-data IS [A-azure-custom-data-2026], with the accompanying "We advise *not* to store sensitive
  data in custom data." A compiled Dorc artifact delivered this way is world-readable to every
  process on the box unless IMDS is locked down. Guards that embed probe *results* are fine; guards
  that embed credentials are a leak by construction.
- Q6 lands better than expected, with one sharp exception. busybox ash is a *fork of dash*
  [A-busybox-ash-source-2024], and the floor's own second pole, posh, is pdksh-derived
  [A-debian-posh-package-2026] — so the floor already straddles two lineages and busybox is the
  *closer* of the two to dash. The only busybox build-toggle that varies in the wild is
  `ASH_BASH_COMPAT`, and everything it gates is already outside the floor. The exception is `echo`:
  busybox has escapes off by default and takes `-e`; dash and posh do the inverse
  [A-busybox-echo-source-2023], and it fails silently both ways.
- Console delivery has no single size threshold — it is a `min()` over layers you cannot enumerate
  from the sending side: 256 chars (BMC-era SOL echo storm, [C-redhat-sol-paste-256-2011], root
  cause paywalled), 2048 (Azure's deliberate client cap [A-azure-serial-console-linux-2026]), 4095
  (Linux canonical line discipline, verified at the kernel [A-linux-n-tty-buf-size-2026]). And SOL
  has no flow control at all [B-ser2net-manpage-2026] — every mitigation in the ecosystem is "slow
  down", never "handshake".
- The console hazard specific to a *generated* artifact: `~` immediately after a newline is an
  escape sequence in ipmitool and in both clouds' SSH-serial [C-ipmitool-manpage-sol-2026],
  [A-gcp-serial-console-troubleshooting-2026]. A compiled payload puts bytes exactly there.
- Container builds cannot converge, structurally: Docker's cache is string-keyed memoization of
  instruction text, the precise inverse of a state check [A-buildkit-dockerfile-reference-2026]. The
  one place convergence would pay is the *warm-base* `docker run` → mutate → `docker commit` loop —
  documented first-party by Chromium [A-chromium-linux-build-instructions-2026], which also
  prescribes one identical script for host and container.
- Re-run-on-clone is a genuine trap: cloud-init decides "first boot" by comparing instance-id
  against a cache, so an image captured from a `manual_cache_clean: true` instance silently never
  applies per-instance config again [A-cloudinit-first-boot-2026].

## Analytical note (NOT a research finding — flagged as reasoning, uncited)

An offline compiled artifact has no probe phase, therefore *nothing can elide*. Every site that
would have become `# converged: …` in a networked `dorc plan` becomes a live runtime guard
`( check ) || cmd` instead. Two consequences worth putting in front of the human before any design
work proceeds:

1. The compiled artifact retains Dorc's **safety** value-prop (non-idempotent commands stop firing
   blind) and loses its **attention** value-prop (DESIGN.md priority 3 — "entirely elide commands
   that aren't relevant"), because there is no measured world to justify a deletion. It also
   partially loses the **performance** prop: guards still cost a local command each.
2. That inverts the poison-wall economics. In networked mode an unmodeled command degrades
   downstream sites from elision to guard. In compiled mode everything is already a guard, so a
   poison wall costs *nothing extra* downstream. The compiled artifact is the regime where oracle
   coverage matters least — which is either a cheap early win or a reason it is the wrong first
   product, and that is a judgment call for the human, not for me.

Deliberately NOT attempted, per the standing quarantine: any estimate of compiled-artifact byte size
derived from repo material. The channel caps below are reported as external facts only.

### Q6 — busybox ash as a dialect floor (gathered + graded by subagent; provisional until re-verified)

> [A-dash-upstream-homepage-2024] (relevance: +1:SURE)
> DASH is a direct descendant of the NetBSD version of ash (the Almquist SHell). I ported it to
> Linux in early 1997. It was renamed to DASH in 2002.

> [A-busybox-ash-source-2024] (relevance: +1:SURE)
> This shell is actually a derivative of the Debian 'dash' shell (by Herbert Xu), which was created
> by porting the 'ash' shell (written by Kenneth Almquist) from NetBSD.
>
> └ so busybox ash is a fork OF dash, not a sibling port — roughly a 2001-vintage dash (Mascheck
>   dates the incorporation to debian ash 0.3.8-5 in busybox 0.52) plus 25 years of divergence
>   [B-mascheck-ash-genealogy-2021].

> [A-debian-posh-package-2026] (relevance: +1:SURE)
> posh is a stripped-down version of pdksh
>
> └ the genealogically load-bearing correction: the welded floor is ALREADY cross-lineage. posh is
>   Korn-derived, not Almquist-derived. busybox ash is *closer* to dash than posh is. Most of the
>   cross-lineage cost of admitting busybox has already been paid.

> [B-posh-manpage-2026] (relevance: +1:SURE)
> Legitimate bugs are inconsistencies between manpage and behavior, and inconsistencies between
> behavior and Debian policy (currently SUSv3 compliance with the following exceptions: echo -n,
> binary -a and -o to test, local scoping).

> [B-posh-manpage-2026] (relevance: +1:SURE)
> NOTE: `$(command)` expressions are currently parsed by finding the matching parenthesis,
> regardless of quoting. This will hopefully be fixed soon.
>
> └ posh's command-substitution parser is not quoting-aware. Directly relevant to any tool that
>   claims to model posh's parse.

> [A-busybox-echo-source-2023] (relevance: +1:SURE)
> /* BB_AUDIT SUSv3 compliant -- unless configured as fancy echo. */
> …
> char eflag = 0;
>
> └ THE headline in-floor divergence. busybox `echo` has escapes OFF by default and takes `-e` to
>   turn them on; dash and posh process escapes unconditionally and treat `-e` as a literal
>   argument. Cross-confirmed by [B-mascheck-echo-printf-2011], which places posh with dash. It
>   fails SILENTLY in both directions — no error, no exit-status signal.

> [B-modernish-shell-caps-2026] (relevance: +1:SURE)
> Busybox ash has a false-friend `[[` that is just an alias of `[`, with none of the shell grammar
> integration!
>
> └ worse than absence: `[[ $v = 'a b' ]]` parses and runs on Alpine with `[`-semantics (word
>   splitting, glob expansion). Also from the same catalogue, busybox-only and unfixed where dash
>   has fixed them: `break`/`continue` escaping non-enclosing loops *and function barriers*
>   (QRK_BCDANGER); multi-byte IFS delimiters broken (BUG_MULTIBIFS).

> [A-alpine-busybox-config-2026] / [A-debian-busybox-udeb-config-2022] / [B-buildroot-busybox-config-2026] (relevance: +1:SURE)
> The only `CONFIG_ASH_*` toggle that actually varies across Alpine, debian-installer's
> busybox-udeb, and buildroot defaults is `ASH_BASH_COMPAT` (Alpine y, d-i not-set, buildroot y).
> `ASH_GETOPTS`, `ASH_CMDCMD`, `ASH_ECHO`, `ASH_PRINTF`, `ASH_TEST`, `FEATURE_SH_MATH` are enabled
> in all three.
>
> └ and everything `ASH_BASH_COMPAT` gates (`pipefail`, `${x//y}`, `${x:o:l}`, `$'…'`, `&>`,
>   `function`, grammar-`[[`, `source`) is *already outside* a dash ∩ posh floor. The theoretical
>   configurability of busybox is far larger than its observed variance.

> [B-ser2net-manpage-2026] (relevance: +1:SURE)
> Serial-parameter setting "does not work on SOL, SOL has fixed N81".
>
> └ flow control over IPMI SOL is not misconfigured, it is ABSENT — there is no XON/XOFF or RTS/CTS

>   [C-ipmitool-manpage-sol-2026], which buys reliability on the network leg and nothing on the
>   BMC→UART leg. Correspondingly, every ecosystem mitigation is "slow down", never "handshake"
>   [B-gnu-screen-paste-manual-2026], [B-putty-wishlist-character-line-delay-2017].

> [C-ipmitool-manpage-sol-2026] (relevance: +1:SURE)

>
> └ the hazard nobody lists and the one that specifically bites a GENERATED artifact: a newline
>   followed by `~` detonates the session. GCP's SSH-serial has the same `~.`/`~B`
>   [A-gcp-serial-console-troubleshooting-2026]; conserver traps `^Ec`
>   [B-conserver-console-client-manpage-2023]. Also opt-in high-bit stripping (conserver `-7`,
>   ser2net 7-databit) destroys non-ASCII bytes before any processing.

> [A-aws-ec2-serial-console-connect-2026] (relevance: +1:SURE)

>
> └ with GCP's equivalent (`ssh -p 9600 …@REGION-ssh-serialport.googleapis.com`)

> #define N_TTY_BUF_SIZE 4096
>
> └ verified at the definition site in `drivers/tty/n_tty.c` after a subagent surfaced the claim
>   from a B-graded forum answer [B-unixse-tty-line-length-limit-2021]. In canonical mode the line
>   discipline buffer is 4096 bytes, so a console-delivered artifact must keep every *line* under
>   ~4095 bytes or the overflow is silently discarded. This is a PER-LINE cap, orthogonal to every
>   per-payload cap in Q1 — and it bites exactly the construct a compiler is tempted to emit: a long
>   inlined guard condition on one physical line.
