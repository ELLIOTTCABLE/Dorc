## Findings

### P1 — the load plane

- P1 has a proved academic ancestor: **scope graphs** define a scope as a minimal program
  region behaving uniformly w.r.t. name resolution, with three checkable uniformity
  properties. 28Q's "frame" is that object and can borrow the definition and the
  well-formedness obligations wholesale. [A-neron-scope-graphs-2015]
- The same theory says sh's `.` is an **include, not an import** — and include is a
  DIFFERENT visibility policy whose efficient environment algorithm explicitly does not
  work. Spelling an include as a module boundary costs the fast algorithm.
  [A-neron-scope-graphs-2015]
- Their WF(p) ∈ P*·I* rule exists to forbid "import a module, then walk to ITS lexical
  parent" — behaviour they say no real language exhibits. sh's `.` exhibits it by
  construction. The load plane's crossing rule cannot be inherited from the module
  literature unexamined. [A-neron-scope-graphs-2015]
- Mutually-recursive imports are the one corner their calculus admits ANOMALIES in even
  with a seen-set: one derivation can resolve a single import two different ways. An
  argument for refusing cyclic `.`-closures rather than deduping them.
  [A-neron-scope-graphs-2015]
- **Optimistic analyses are wrong when halted early; pessimistic ones are merely poor.**
  Anything in the kernel starting from "assume live and lower on evidence" cannot be
  budget-capped, timed out, or read off mid-fixpoint. [A-wegman-zadeck-sccp-1991]
- Reachability flags must key to **edges, not nodes** — node-keying provably loses facts.
  The kernel's positional keys should be transitions between statements, not statements.
  [A-wegman-zadeck-sccp-1991]
- A def-use-chain-shaped index is both quadratic AND less precise than an SSA-shaped one,
  because def-use chains exist along non-executable paths. §1's "DefinitionId + frame →
  live-definition map" is def-use-chain shaped; the φ-function discipline is the known
  repair, and the built hash-munge is already SSA renaming in disguise.
  [A-wegman-zadeck-sccp-1991]
- Positive prior-art for the unification thesis itself: fusing constant-propagation with
  unreachable-code elimination into ONE fixpoint beats iterating them separately — the
  same claim §1 makes retiring the veto, `live_source`, and `never_live`.
  [A-wegman-zadeck-sccp-1991]
- **Entry-point context-sensitivity is the thing that disambiguates, and it is measured.**
  The only empirical study of this exact problem shows file-local resolution leaves
  genuine ambiguity that only knowing the ENTRY resolves. [A-hills-php-includes-resolution-2014]
- …and it prices the pillar brutally: file-local resolution ~5 ms median and IDE-grade;
  entry-context resolution 17.5 s median, explicitly declared unsuitable for interactive
  use — and it bought NOTHING in two of five systems tested.
  [A-hills-php-includes-resolution-2014]
- Three independent systems converged on 28Q's `funcenv-reads-source-literal-plane-only`
  restriction, each for its own reason: PHP AiR refuses variable VALUES for soundness
  against reflection [A-hills-php-includes-resolution-2014]; Sorbet refuses because
  definition-discovery cannot depend on evaluating expressions without a logical cycle
  [A-sorbet-unsupported-features-2026]; and the phase-distinction literature derives the
  same restriction from decidability [B-phase-distinction-requirement-manuscript-1988].
- The entry SET must be GIVEN, never inferred — identifying which files are entries "would
  assume the analysis we are implementing". Dorc dodges this because the CLI names the
  entry; it should keep dodging it. [A-hills-php-includes-resolution-2014]
- A shipped, widely-used gradual type-checker flatly REFUSES P1's problem, and one of its
  four stated reasons is verbatim 28Q's `res-host-conditional-loading` case: two versions
  of a file, only one loaded at runtime, "no way to indicate that to Sorbet".
  [A-sorbet-unsupported-features-2026]
- Sorbet's engineering argument for hard restrictions is worth stealing: the invariant pays
  for itself across the whole codebase — "no need to defensively handle arbitrary code" —
  and it records one phase-ORDER choice that could not be backed out later.
  [A-sorbet-unsupported-features-2026]
- **The complete state of the art for `source` resolution in shell is four rules long**, and
  no shipped shell tool does entry-relative resolution at all.
  [A-bashls-source-resolution-2026]
- Positional directive attachment is brittle in a way 28Q can measure: it keys to the
  immediately-previous sibling node, so wrapping the source statement in any compound
  command silently defeats it. [A-bashls-source-resolution-2026]
- `.`-resolution is a DISK READ (`existsSync`) and must sit behind Dorc's DI seam to stay
  hermetic. [A-bashls-source-resolution-2026]
- Psalm has shipped a knob for nearly every axis 28Q is choosing on, and its DEFAULT is the
  opposite pole: it abandons the single true load order and unions over "all possible
  permutations of file include order", calling order-respecting faster and more faithful
  but "potentially less comprehensive". [A-psalm-include-configuration-2026]
- Psalm also ships the load-plane/value-plane split as a perf knob (functions, constants and
  classes survive; variables do not), whole-unit-global resolution as a legacy concession —
  which is exactly the as-built behaviour §1 is leaving — and an autoloader hook that
  EXECUTES user code, the road Sorbet refuses. [A-psalm-include-configuration-2026]

### P1 — base rates (does the bet pay?)

- The optimistic bound, measured: across 19,816 PHP files, 78%+ of dynamic includes are
  actually static, and after resolution **93.2% of all include sites are statically known,
  6.8% irreducible**, with residue concentrated in 5.0% of files.
  [A-php-dynamic-include-resolution-2013]
- That paper also enumerates WHAT makes a computed name recoverable (literal array in a
  foreach, equality against a literal, switch/case arms, literals under a constrained set of
  string ops) — a ready-made safe-list shape for the load plane.
  [A-php-dynamic-include-resolution-2013]
- **The shell measurement 28Q actually wants does not exist.** No published work breaks
  `.`/`source` targets into literal vs computed. [B-debian-shell-corpus-statistics-2017]
- What does exist inverts the PHP/JS framing in Dorc's favour: across 31,521 Debian
  maintainer scripts, `.` occurs 4,922 times in 2,900 files (5th most frequent builtin)
  while `eval` occurs 42 times in 30 scripts and `alias` twice — roughly **117:1**. The
  loading construct is mainstream; the defeating construct is vestigial.
  [B-debian-shell-corpus-statistics-2017]
- The nearest published substitute, same corpus and same tool: `for`-list staticity asks the
  identical question and answers **≥59%**, computed as a floor by disqualifying any list
  containing a variable at all, with no constant propagation. The PHP evidence suggests
  constant propagation moves such a number a long way up.
  [B-debian-shell-corpus-statistics-2017] · [A-php-dynamic-include-resolution-2013]
- Corroborating negative evidence: the CoLiS shell→intermediate translator succeeds on 77%
  of Debian maintainer scripts and names globs, parameter modifiers and advanced
  redirections as the causes — unresolvable `.` targets are NOT on that list, despite `.`
  being the 5th most common builtin. (Cited from the STTT-2022 platform paper already
  graded in the main `Research/sources.json`.)
- The standing counter-evidence: a whole literature assumed the good case about JavaScript
  and was wrong, and the assumption that failed hardest was "eval is infrequent and doesn't
  affect semantics" — structurally the assumption a `.`-kernel makes about its escape hatch.
  It also kills the "initialization phase" folklore the load plane leans on.
  [A-javascript-assumptions-violated-practice-2010]
- The sharpest coverage warning: eval proper was a MINORITY of JavaScript's dynamic-code
  entry points. A kernel that resolves `.` while ignoring command substitution into a sourced
  path and computed interpreter dispatch will report a resolution rate far better than its
  true coverage. [A-eval-taxonomy-large-scale-2011]
- Empirical support for definition-keying: call sites are overwhelmingly monomorphic IN
  SHAPE even where the language permits anything — 98.6% of sites only ever see one
  syntactic pattern. [A-eval-taxonomy-large-scale-2011]
- **The loading construct specifically resists the optimistic bucket.** In Ruby, ~2/3 of
  dynamic-feature usage is "essentially static" — and `require` contributes ZERO to that
  two-thirds. All 15 non-constant sites land in the environment-dependent buckets the
  authors exclude. Computed load targets are not arbitrary, but they are
  ENVIRONMENT-dependent rather than statically determined — which is
  `res-host-conditional-loading`'s exact shape. [B-ruby-dynamic-features-nearly-static-2009]

### P2 — the entry-closure as speaker

- **P2's dedup clause is keyed to the wrong thing.** The only source that adjudicates
  dedup-vs-refuse directly tests MODULE IDENTITY — the source constructor applied to the
  identities its imports resolved to — explicitly not source text. Two byte-identical
  helpers whose own sourcing resolved differently are DIFFERENT speakers, and deduping them
  silently merges two authorities. Restate the clause over closure-identity.
  [A-backpack-identity-not-bytes-2014]
- The fence belongs in the closure-UNION operation, not in a post-hoc check: the same source
  argues the fix for two-instances-one-vocabulary is to make merging itself fail.
  [A-backpack-identity-not-bytes-2014]
- **The fence has a predicted false-positive mode and the corpus names it.** Two entry files
  that each source one shared helper produce two closures, two speakers, fence fires — the
  diamond case, shipped unresolved and flagged as future work because there was no manifest
  to declare sharing in. "No manifest" is precisely what forecloses the obvious fix.
  [A-units-cool-modules-hot-1998]
- The positive precedent from the same source: check agreement by proving two occurrences
  "have the same source in the link graph" — keying attribution to link-provenance rather
  than to a name. [A-units-cool-modules-hot-1998]
- A foundational calculus with free design latitude chose the STRICTEST answer — shared
  import specs fine, identical type exports fine, but a component "may not be a term export
  in both modules" — and Backpack relaxed it within six years, by name. Two-point
  calibration curve. [A-mixml-specified-not-defined-2008] · [A-backpack-identity-not-bytes-2014]
- A rule worth stealing outright: no operator may remove a module's imports from scope,
  because "one should not be allowed to forget about a requirement". If a closure has an
  unsatisfied requirement, no downstream operation may hide it.
  [A-mixml-specified-not-defined-2008]
- If the entry-closure is bidirectional (helpers see the entry's vocabulary and vice versa),
  P2 has bought the **double vision** problem and with it a two-pass typechecker, budgeted
  or not. [A-mixml-specified-not-defined-2008]
- **The fence is a zero-sum transfer, and the plan has not priced the upstream side.** Every
  mint a helper closure may perform is one the entry closure can no longer perform without
  breaking downstream — so once one closure owns a vocabulary, adding a member later is a
  breaking change for every downstream book. [A-rebalancing-coherence-zero-sum-2015]
- The user-facing cost has a name and a first-party admission that it is "annoying": the
  newtype tax. Dorc's analogue is forcing an admin to mint a shim vocabulary purely to
  launder ownership — exactly the ceremony the no-manifest pitch promises to avoid.
  [A-rebalancing-coherence-zero-sum-2015] · corroborated from a second ecosystem in
  [C-haskellwiki-orphan-instance-composability-2026]
- Both ecosystems that shipped this needed an ESCAPE VALVE fast: Rust shipped
  `#[fundamental]` in the same RFC, explicitly unstable and incomplete, because the base
  rules could not compile the popular crates. P2 currently has the hard line with no valve.
  [A-rebalancing-coherence-zero-sum-2015]
- The failure story to motivate the fence is sharper than link-order nondeterminism: "your
  program might stop compiling just by using two crates with an overlapping impl" — breakage
  in an innocent third party who merely composed two working things. That is an admin
  sourcing two oracles that each mint the same vocabulary.
  [A-re-rebalancing-coherence-order-2018]
- Caution on fence mechanics: Rust kept a POSITIONAL rule that most library authors are
  unaware of and that forces API designers to order parameters by likelihood of downstream
  override. Any P2 rule whose correctness depends on declaration order inherits this.
  [A-re-rebalancing-coherence-order-2018]
- The ecosystem cost P2 does not acknowledge: senior Rust folk seriously float abandoning
  the orphan rule for a social norm, because it makes cross-ecosystem GLUE crates impossible
  — nobody can publish a bridging oracle teaching oracle A about oracle B's vocabulary.
  [A-re-rebalancing-coherence-order-2018] · the plugin-architecture dissent in
  [C-haskellwiki-orphan-instance-composability-2026]
- **A performance argument FOR single occupancy that the plan has not claimed.** An
  instance living with its class or type is free because the compiler read that interface
  anyway; an orphan forces eager reading of every orphan interface below the target,
  unprunable, "usually wasted work, but there is no avoiding it". Closure-local minting is
  what lets the engine read only what the entry closure reaches.
  [A-ghc-orphan-modules-eager-read-2025]
- How to DEFINE closure-locality: not "declared in this file" but reachability through the
  inference relation. GHC had to amend its own definition once it found a case (functional
  dependencies) where syntactic appearance and relevance diverged.
  [A-ghc-orphan-modules-eager-read-2025]
- **Coherence is a soundness precondition for elision, not a style rule.** The optimiser
  ASSUMES coherence and substitutes dictionaries accordingly, so incoherence becomes
  observable miscompilation with live bug numbers. If Dorc elides or replaces on the
  strength of a vocabulary member's contract and two closures disagree, the elision is
  wrong at runtime and nothing errored. [A-ghc-overlapping-instances-incoherence-2025]
- …and it refines the fence's trigger: the danger is not that the engine cannot pick, it is
  that it picks locally and silently, DIFFERENTLY in each place. A fence that fires only
  when two minters are simultaneously visible misses the common case.
  [A-ghc-overlapping-instances-incoherence-2025]
- The un-excludability argument is the premise the fence rests on: sourced minting is
  unnamed and un-excludable at the sourcing site — you cannot write
  `. ./helper.sh hiding (frobnicate)`. If P2 wants an alternative to the fence, that is
  what it would have to build. [C-haskellwiki-orphan-instance-composability-2026]

### P2 — what the ops ecosystems landed on, and their regret

- The spread is clean and the regret is diagnostic. **Hard error at declaration**: Puppet
  (no regret, presented as deliberate correctness) [A-puppet-resource-uniqueness-failure-2026]
  and Debian Policy (no regret, settled doctrine) [A-debian-policy-file-ownership-2026].
  **Total precedence order**: Chef attributes [A-chef-attribute-precedence-inversion-2023]
  and Ansible [A-ansible-twentytwo-level-precedence-2026], both with regret.
  **Silent merge**: Chef resources, repudiated in writing
  [A-chef-resource-cloning-deprecation-2017]; nixpkgs overlays, still shipping
  [B-nixpkgs-overlay-order-matters-2025].
- Chef's stated cause for repudiating silent merge is sharper than the usual
  conflicting-values one and matches Dorc's: name collision destroys the ability to ADDRESS
  a member by name. [A-chef-resource-cloning-deprecation-2017]
- **Chef is the cautionary case for the fence's nearest alternative.** The design doc names
  the cross-package collision — the "Conflicting Community Cookbook Case", precisely the
  fence's motivating scenario — then downgrades it ("I have personally not seen this in the
  wild"), and the shipped code handles exactly that case worst: a plain Hash assignment,
  silent last-wins on the name, no diagnostic. A fence that DECLINES is strictly better than
  a namespace that silently last-wins, and Chef's own artifact is the evidence.
  [A-deleo-chef3694-design-proposal-2013] · [A-chef-shipped-resource-set-2026]
- Puppet widened the KEY rather than weakening the rule when one key proved too coarse
  (composite namevars), and its sanctioned escape is a re-architecture of the declaration
  site — declare once, realize many times — not a precedence rule.
  [A-puppet-resource-uniqueness-failure-2026]
- Debian's answer is uniquely SYMMETRIC: no consensus means BOTH parties are renamed, nobody
  wins the name by default. It also has one rule per collision KIND, an owner plus a
  mediated-write API so non-owners can still act, and a grandfather clause freezing
  pre-existing collisions while forbidding new ones — a worked lesson in introducing a fence
  into an already-populated namespace. [A-debian-policy-file-ownership-2026]
- **Total precedence orders do not survive contact with their own maintainers.** A 22-slot
  order was wrong in implementation relative to its own documentation from roughly slot 8
  downward, undetected until someone wrote a differential harness; core maintainers had to
  ask each other which of two slots outranked the other.
  [A-ansible-runtime-order-mismatch-2017] · [A-ansible-twentytwo-level-precedence-2026]
- Two slots of Chef's 15 are ORDERED BACKWARDS relative to each other because one total
  order could not satisfy both use cases — the doc has to stop and explain it.
  [A-chef-attribute-precedence-inversion-2023]
- Making merge a global config knob is its own failure mode: you cannot enable it for the
  one case that needs it without enabling it everywhere.
  [A-ansible-twentytwo-level-precedence-2026]
- A total order whose reference manual must pre-empt the reader's intuition twice on one
  page is not carrying its weight. [A-ansible-general-precedence-categories-2026]
- **The fence's scope limit, demonstrated twice independently.** `ldconfig` does not honour
  dpkg diversions, so the override is a property of dpkg's MODEL of the filesystem and a
  second namespace defeats it silently [A-dpkg-divert-view-scoped-override-2025]; nixpkgs
  single-package overrides do not propagate to consumers who resolved through the package
  set [B-nixpkgs-overlay-order-matters-2025]. If a Dorc-side name is reachable other than
  through the engine's own resolution, the fence covers less than it appears to.

### P3 — availability, lifetimes, incarnations

- **The counter-thesis names the obligation precisely, and it is discharge-or-decline, not
  forbidden.** Answering a STATIC question must not reduce to deciding equality of RUN-TIME
  expressions, or it becomes undecidable. The repair was NOT syntactic restriction — it was
  equations splitting every module into a compile-time part and a run-time part.
  [A-phase-distinction-higher-order-modules-1989]
- Generalised, and this is the sentence to put in front of the two-plane unification: one
  object may not play both roles at once — a quantity that is simultaneously a run-time
  value and a static index is exactly what the requirement deletes. That is the shape of
  consulting an incarnation counter or a host identity statically.
  [B-phase-distinction-requirement-manuscript-1988]
- The escape hatch and its precondition: a run-time quantity MAY be lifted to the static
  level, but only if it is pure/side-effect-free, and the two copies must stay syntactically
  distinct. The reward for keeping the separation is that side-effects cannot propagate into
  the static plane at all. [B-phase-distinction-requirement-manuscript-1988]
- The modern, quantified version: 1ML performs exactly 28Q's move (collapse two stratified
  layers) and itemises the bill — a universe distinction reintroduced semantically, type
  inference incomplete on three axes, subtyping LOSES REFLEXIVITY, conditionals require
  annotation. [A-unification-costs-predicativity-restriction-2015]
- Two transfers from it. **No-lattice**: if the kernel's join at a control-flow merge over
  two-plane facts has no least upper bound, the design owes an annotation at every merge or
  silently picks a non-principal answer. **The admission ticket**: unification is only
  affordable because an EFFECT DISCIPLINE certifies per-expression phase-separability. Read
  onto shell, `. "$(pick_impl)"` fails because a command substitution is not
  phase-separable, and the literature's answer is not "reject sourcing" but "have a purity
  judgment and admit only the pure". [A-unification-costs-predicativity-restriction-2015]
- **The two-sided context is off-the-shelf; the ONE-discipline claim is not.** Modal systems
  carry a name AND a world on every hypothesis in one context — but govern the two planes
  with orthogonal rule sets, and the world plane needs FOUR separate devices (a type-level
  mobility predicate, a value-level portability witness, a world-internalizing proposition,
  and a motion rule) that the scope plane needs none of. The defensible claim is "one
  context, two planes, two disciplines, one crossing-rule per plane".
  [A-worlds-are-network-nodes-2004] · [A-modal-worlds-as-hosts-2007]
- A cut 28Q will need regardless of the rest: a fact is **FOR a world rather than AT it** —
  the place it is licensed for versus where its representation currently sits. Its sibling:
  marshaling is not mobility; any well-typed value can be serialized, only some are mobile.
  [A-modal-worlds-as-hosts-2007]
- Also transferable: isolate ALL cross-world communication into one rule so the other rules
  avoid action-at-a-distance — the principle behind a single entry-form seat.
  [A-worlds-are-network-nodes-2004]
- **The cautionary tale closest to Dorc's domain fails at ABSTRACTION, not at place.** Links's
  static tier-assignment was sound and degraded silently and catastrophically the instant a
  predicate moved behind a parameter, and could not survive abstraction over generated names
  at all. One cause: place was assigned LEXICALLY, so any construct decoupling a name from
  its lexical site destroyed the assignment. `.`-sourcing, `eval` and computed paths are
  exactly such constructs. [B-single-language-three-tiers-2006]
- **The best correlate-don't-divorce precedent is not an identity scheme — it is Raft.** It
  KEEPS pre-boundary entries, KEEPS their original term numbers, and still refuses to let
  them commit on their own evidence; they ripen only when joined to a fact established under
  the CURRENT term. Read onto §3: evidence from incarnation N does not ripen by accumulating,
  only in conjunction with at least one N+1 fact. [A-raft-terms-logical-clock-2014]
- The reuse ban with a conditional escape hatch, and the hatch is ORDERING EVIDENCE: an
  identifier may be retained past its natural death for the same purpose, provided sequence
  continuity is maintained. Correlation across the boundary is licensed by carrying the
  sequence, not the name. [A-volatile-filehandle-expiry-distinction-2020]
- **The most transplantable sentence in the round for a soundness-capped analyzer**: identity
  comparison is licensed to improve PERFORMANCE, never correctness, and clients must be
  prepared for cases where sameness cannot be determined.
  [A-volatile-filehandle-expiry-distinction-2020]
- The two-error split 28Q's vocabulary needs: "the object is gone" versus "your handle is
  unusable, the object may well still exist" — distinguished by folding server boot time
  into the handle. [A-volatile-filehandle-expiry-distinction-2020]
- Fail-closed is a SPECTRUM, not a binary, and 28Q's guard/replace/elide ladder needs the
  middle rungs: a hard error [A-pidfd-signal-fails-closed-2026]; a recoverable-vs-final split
  [A-volatile-filehandle-expiry-distinction-2020]; and, when the far end cannot verify the
  token at all, degradation from verification to a TIMED QUARANTINE
  [A-chubby-instance-number-epoch-2006].
- A handle binds to an INSTANCE, not a name — calls fail if the node was deleted since the
  handle was created, even if recreated — and a new master must fence packets addressed to
  its predecessor "even one running on the same machine".
  [A-chubby-instance-number-epoch-2006]
- An argument for DST coverage of the lifetime boundary specifically: the fail-over path
  "has been a rich source of interesting bugs" precisely because it is exercised far less
  than the rest. [A-chubby-instance-number-epoch-2006]
- The incarnation guarantee is CONDITIONAL and a concurrent actor can destroy it: the handle
  holds only while the process is prevented from being reaped, and reaping can happen in a
  thread you do not control. [A-pidfd-open-zombie-conditions-2026]
- Choosing which EVENT ends an availability window is a real decision: the stale-handle error
  fires on reaped, not on dead — between exit and reap the handle still resolves.
  [A-pidfd-signal-fails-closed-2026]
- The motivating consumers for instance-handles were SUPERVISORS correlating across a
  lifetime they did not open — Dorc's exact position relative to a host it did not boot.
  [B-pidfd-open-commit-rationale-2019]
- The three-role split to steal: **uid** = which incarnation (its definition exists purely for
  the destroy-and-recreate case), **generation** = which revision of intent,
  **observedGeneration** = how far the actor has caught up.
  [B-kubernetes-uid-generation-conventions-2026]
- ⚠ A live first-party contradiction found this round: Kubernetes now says resource versions
  ARE orderable within a resource type and made it a conformance requirement at 1.35
  [A-resource-versions-now-orderable-2026], while the community API-conventions document,
  touched 2026-07-14, still says they MUST be treated as opaque
  [B-kubernetes-uid-generation-conventions-2026]. Neither acknowledges the other. Any design
  citing Kubernetes as precedent for opaque-version discipline must pin which document.
- **Lifetime policy is contagious across a dependency graph, and selective application is
  likely UNSATISFIABLE, not merely inconsistent**: "in any non-trivial acyclic subgraph,
  reversing half the edges is likely to result in a cycle". If an oracle or book can declare
  incarnation-sensitivity per-object, it propagates whether or not the engine models it that
  way. [B-cycle-argument-maintainer-explanation-2019]
- …and the propagated flag has to be DURABLE — it is the one lifecycle flag Terraform must
  persist to state, precisely because the contagion must survive across runs. That collides
  head-on with §3's kSTATE-untouched, nothing-persists posture.
  [B-create-before-destroy-propagates-2026]
- Host-identity stability is a property of someone else's PROVISIONING DISCIPLINE, not of the
  machine: golden-image workflows must actively blank the machine-id or every clone shares an
  identity. [A-machine-id-survives-reinstall-2026]
- The sharpest this-only-holds-if in the round: a fresh-per-boot marker only discriminates
  lifetimes at the rate the host actually reboots, and on a long-uptime host it silently
  acquires machine-id-like properties. Treating boot-id-unchanged as
  nothing-happened-in-between trusts a signal that has gone quiet, not one that was verified.
  [A-boot-id-per-kernel-instance-2026] · weaker corroboration only in
  [B-boot-id-generated-once-2026]
- Unrequested find worth a follow-up: systemd already ships a finer-grained
  per-service-activation incarnation marker (the invocation ID), which is the closest
  existing prior art to what §3 is minting. [A-boot-id-per-kernel-instance-2026]

### P3 — state over program positions (typestate, lifetimes, definite assignment)

- **An availability window is a POINT-SET, not an interval.** Lifetimes as sets of CFG
  points may have GAPS, because the same variable can be written, used and rewritten — and
  Rust's earlier design, which required continuous regions, is recorded as exactly what
  made one of its problem cases unfixable. Typing §3's window as an interval silently
  over-approximates every re-creation. Corroborated by two others computing state
  per-position with no continuity requirement. [A-lifetimes-as-program-points-2017] ·
  [A-vault-keys-held-set-2001] · [A-definite-assignment-syntactic-conservatism-2023]
- **Liveness, not scope, should drive the window**: the primitive is "may be used later",
  so a context's window should be driven by whether any LATER command consumes a fact about
  it, not by where the creating command sits. [A-lifetimes-as-program-points-2017]
- The pre-existing argument against "just SSA the script": location-aware subtyping
  explicitly rejects both SSA and per-point-types as alternatives, with a worked
  discriminating example. [A-lifetimes-as-program-points-2017]
- **Two-track liveness for teardown**: destruction is allowed a WEAKER freshness requirement
  than use. Dorc plausibly has three tracks — read, mutate, destroy — and requiring
  identical freshness for all three is over-conservative and costs eliminations.
  [A-lifetimes-as-program-points-2017] · read-side analogue in
  [A-access-permissions-modular-typestate-2007]
- Non-terminating regions break reverse/liveness analysis because the CFG has no exit; the
  repair is synthetic edges so a final node postdominates everything. Dorc has the same
  hazard with `while true` supervisor loops and with `exec`.
  [A-lifetimes-as-program-points-2017]
- **The held-key set is an availability environment already built.** Compile-time tokens
  each carrying a state name, computed per-CFG-node, created by allocation and destroyed by
  revocation, neither duplicable nor losable — `useradd`/`userdel` as grant/revoke, with
  effect clauses over the set as the shape an oracle contract should take.
  [A-vault-keys-held-set-2001]
- …and the same source gives the mechanism for turning "I statically know the context is
  available" into a runtime value and back, which is what a shell guard on a probe's exit
  status has to do. [A-vault-keys-held-set-2001]
- **Collections anonymize.** Once a tracked resource enters a collection the checker knows
  SOME token guards it but no longer WHICH. Any Dorc construct that puts hosts in a list and
  iterates loses per-host identity the same way, and the fix is structural (carry the
  correlation in the data), not analytical. [A-vault-keys-held-set-2001]
- **Freeze versus forget is a real fork, and §3 should pick deliberately.** One system chose
  FREEZE — the moment aliasing becomes unknown, state is permanently fixed at its last known
  value and can never change again [A-typestate-frame-alias-confinement-2004]. Its successor
  chose FORGET — weak permissions lose state knowledge after every effectful step but can
  re-acquire it via dynamic state tests, and explicitly frames itself as fixing the
  predecessor's over-restriction [A-access-permissions-modular-typestate-2007]. Read onto
  Dorc: the instant it cannot enumerate every path that could mutate a context (a cron entry,
  a second admin's session, a detached subshell), freeze makes every fact about that context
  read-only-forever rather than merely stale. Forget's price is that dynamic state tests must
  be FIRST-CLASS in the analysis — probe commands and their exit statuses inside the model,
  not outside it.
- **The state guarantee is the only graceful-degradation primitive in the round**: a
  permission rooted at a node of a hierarchical state space guarantees the object cannot
  leave that subtree even under concurrent modification. Coarse knowledge survives while
  fine knowledge is surrendered — "the host is still reachable" outliving the event that
  destroys "its daemon is still at version X". Everything else in the corpus is
  all-or-nothing. [A-access-permissions-modular-typestate-2007]
- Weak-permission state facts are not stale-after-a-timeout; they are **invalidated by the
  very next effectful step**. That is the precise worth of a probe fact when the host is not
  exclusively held. [A-access-permissions-modular-typestate-2007]
- State DIMENSIONS (orthogonal decompositions) are how netns facts avoid being invalidated
  by a filesystem mutation; fractions are the accounting device that lets a split permission
  be REJOINED — the formal answer to when Dorc may re-acquire the right to mutate a context
  it previously shared out. [A-access-permissions-modular-typestate-2007]
- **Partial states must be nameable.** A state change is implemented as a SEQUENCE of
  updates, so intermediate configurations exist and must be describable; the successor
  system needs intermediate states no client ever observes. A host mid-provision is a real
  state, and if the analysis has no name for it every interrupted book is unanalyzable on
  resume. [A-typestate-frame-alias-confinement-2004] ·
  [A-access-permissions-modular-typestate-2007]
- The frames-plus-abstract-rest-state shape is ready-made for "what we modelled about this
  host" versus "what we are forced to assume about everything below it", and pack/unpack is
  a good model for the seam between an oracle's declared abstraction and raw command
  observation. [A-typestate-frame-alias-confinement-2004]
- **Why a position-indexed analysis should be SYNTACTIC, and the reason is not
  tractability**: it must be identically decidable by every conforming implementation, or
  the accept/reject boundary becomes a property of the toolchain rather than the language.
  An analyzer whose acceptance set drifts with its own improvements is one whose users
  cannot write portable books. [A-definite-assignment-syntactic-conservatism-2023]
- The judgement shape to borrow: position-relative predicates split into after-when-true and
  after-when-false for boolean expressions, so flow-sensitivity survives without consulting
  values; and a four-valued lattice whose fourth cell (both assigned AND unassigned) is
  reserved for UNREACHABLE code. 28Q should check whether its `never` cell is the same cell —
  in Java the merge is deliberate and is what makes dead code cost nothing.
  [A-definite-assignment-syntactic-conservatism-2023]
- The loop rule breaks the naive circularity with a HYPOTHETICAL judgement — assume, then
  discharge — rather than a fixpoint over iterations. Any "this context survives the loop"
  rule needs the same move. [A-definite-assignment-syntactic-conservatism-2023]
- **Uncorrelated guards are universally rejected, and two independent systems two decades
  apart prescribe the same fix**: reify the correlation into a value. Java rejects
  `if (flag) k=3; if (!flag) k=4;` while accepting the `if/else` form; Vault rejects the
  structurally identical program and calls it "a common limitation of the type checking
  approach". A book doing `if host_has_user; then …; fi` and later
  `if ! host_has_user; then …; fi` is the same pattern — and the interesting open question
  is what the idiomatic-sh spelling of "reify the correlation" is (plausibly a variable
  carrying the probe result, which is native rather than a Dorc invention).
  [A-definite-assignment-syntactic-conservatism-2023] · [A-vault-keys-held-set-2001]
- A discipline note worth copying: the spec explains that its "definitely unassigned after a
  method call" rule is sound ONLY because the property applies exclusively to blank finals
  no other method can assign. Any Dorc claim of the form "this command cannot have destroyed
  the context" owes an equally explicit statement of what makes it true.
  [A-definite-assignment-syntactic-conservatism-2023]

  environment. The CMU scan and the ENSIIE mirror are md5-identical, and object inspection
  shows a pure fax-encoded page-image PDF: fifteen CCITTFaxDecode streams, sixty image

  deliberately. Human-in-the-loop unblock if it ever matters: open the CMU PDF in any
  OCR-capable viewer and paste the text, or install poppler-utils plus tesseract. The
  substitute obtained is [A-vault-keys-held-set-2001], whose related-work section restates the
  1986 model's shape and its known fatal limitation (no aliasing permitted at all) from a
