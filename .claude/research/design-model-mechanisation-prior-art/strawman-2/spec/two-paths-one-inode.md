# Two paths, one inode

> STRAWMAN, chat-tier, unrun. One normative document in the fence convention. Prose outside a
> fence is commentary and binds nothing. Fences bind: `names` declares the words, `claims`
> holds user speech, `alloy` holds Dorc's rules, `normative` holds rules no fence can hold,
> `sh` holds books. A word in braces is a shell word in a shell-word position, drawn from
> `names`; it may expand to several words. Duplicating a `names` or `claims` line in another
> document is allowed; drift under one id is a lint failure; a variant is reminted.

## Lexical forms (commentary)

A `claims` line is `claim <id> <speaker> <static|derived> <inputs> -> <outputs> ; danger <token> ; "<proposition>"`.
A static claim is lifted before any host is touched and takes no world input. A derived claim
is a function the engine runs with world input; its output is a measure. Both are claims;
only the second can be wrong about a host, and only the first can be wrong about the world.

A `names` line is `speaker <id> describes <classes>`, `class <id> "<gloss>"`, or
`instance <id> <class> <value>`. Instances are global: `{a-path}` is `/srv/a/shared` in
every document that uses it; a different constraint mints a different name.

In an `sh` fence, a line beginning `#}` is a normative site line, lexed as shell, every word
a brace-name; the line beneath it is its concrete inhabitant, produced by expanding each
name. `#}=` marks a measure line: it discharges derived claims rather than being a site under
test. `#>` lines are book directives. A trailing `#=> <verdict>` on a `#}` line is the
expected product verdict for that site, `run`, `elide`, or `guard`, with `by <claim ids>`
naming what an `elide` rests on; that set must be sufficient and minimal. `run` means the line
is drifted and executes; `elide` and `guard` presuppose the line's own check converged.

## § 1 The question (mechanized)

Dorc removes a line only on connected claims that the line is unnecessary. Whether an earlier
line's write and a later line's read touch one thing is identity. The rule this section binds
is the one every other section serves.

```alloy
open generic
-- generic supplies: Decl {speaker, danger}, True, Ans {weaker}, Query, answer, wrong, restsOn,
-- and the six checks: neverWrongWhenAllTrue, monotoneInSpeech, strangerSafe,
-- attributionHonest, attributionSufficient, attributionMinimal.
one sig SAME, DISJOINT, KNOWN_UNSPOKEN, UNKNOWN extends Ans {}
fact answerOrder { weaker = UNKNOWN->SAME + UNKNOWN->DISJOINT + UNKNOWN->KNOWN_UNSPOKEN + KNOWN_UNSPOKEN->DISJOINT }
fact safeAnswers { Safe = UNKNOWN + KNOWN_UNSPOKEN }
fact consumerMap { spares = DISJOINT }
```

## § 2 Schemes are forall claims over spellings; sorts are where instances live (mechanized)

A scheme is not a fact about the world. It is a claim of the shape `{spelling} -> {thing}`,
made by one speaker, quantified over every spelling of that class. An instance is placed in a
sort by a measure, `{a-path} -> {inode-x}`, quantified over one thing. The two quantifiers
run in opposite directions: a forall claim declares a way of writing; an exists claim places a
thing under it.

```claims
claim tessa-path-is-a-way-of-writing-1   tessa  static   {path} -> {entry} in {directory}         ; danger none  ; "a path spelling names one entry per component, each looked up in the directory the previous one named"
claim tessa-entry-names-an-inode-1       tessa  static   {entry} -> {inode} in {filesystem}       ; danger none  ; "an entry names one inode number in the filesystem that holds the directory"
claim tessa-inode-names-one-file-1       tessa  static   {inode} in {filesystem} -> exactly one {file}   ; danger wSAME ; "equal inode numbers within one filesystem reach one file"
claim tessa-file-has-one-inode-1         tessa  static   {file} in {filesystem} -> exactly one {inode}   ; danger wDISJ ; "a file has one inode number within its filesystem"
claim tessa-entries-may-share-an-inode-1 tessa  static   {inode} -> any number of {entry}               ; danger none  ; "several entries may name one inode; a path spelling does not name a file uniquely"
```

```alloy
sig Thing {}                                            -- a referent; the engine never holds one
sig Val {}                                              -- bytes
sig Scheme { yields: lone Scheme }                      -- one atom per forall claim of shape {X} -> {Y}
sig Key { scheme: one Scheme, value: one Val, parent: lone Key, reaches: one Thing }
sig Store in Key {}
fact storesAreWellFounded { no k: Key | k in k.^parent }

sig Yields         extends Decl { from, to: one Scheme }          -- tessa-path-is-a-way-of-writing-1, tessa-entry-names-an-inode-1
sig UniqueReferent extends Decl { on: one Scheme }                -- tessa-inode-names-one-file-1
sig UniqueName     extends Decl { on: one Scheme }                -- tessa-file-has-one-inode-1
sig Withheld       extends Decl { on: one Scheme }                -- tessa-entries-may-share-an-inode-1: no UniqueName on the path scheme

fact meaningWhenTrue {
   all d: Yields & True | d.from.yields = d.to
   all d: UniqueReferent & True, a, b: Key |
      a.scheme = d.on and b.scheme = d.on and a.parent = b.parent and a.value = b.value implies a.reaches = b.reaches
   all d: UniqueName & True, a, b: Key |
      a.scheme = d.on and b.scheme = d.on and a.parent = b.parent and a.reaches = b.reaches implies a = b
}
```

```filed
filed tessa-path-is-a-way-of-writing-1    as Yields          from {path}  to {entry}
filed tessa-entry-names-an-inode-1        as Yields          from {entry} to {inode}
filed tessa-inode-names-one-file-1        as UniqueReferent  on {inode}
filed tessa-file-has-one-inode-1          as UniqueName      on {inode}
filed tessa-entries-may-share-an-inode-1  as Withheld        on {path}
```

The `filed` fence is this coordinate's reading of each claim into a rule. It churns when
the rules churn; the `claims` fence does not.

## § 3 A store that exposes nothing else (mechanized)

```claims
claim simon-ext4-exposes-nothing-else-1  simon  static   {filesystem} -> no {inode} reachable through another {filesystem}  ; danger wDISJ ; "an ext4 filesystem exposes its inode numbers through no other filesystem"
```

```alloy
sig AliasesNothingElse extends Decl { store: one Store }
fact meaningWhenTrue2 {
   all d: AliasesNothingElse & True, k: parent.(d.store), k2: Key | k2.reaches = k.reaches implies k2.parent = d.store
}
```

```filed
filed simon-ext4-exposes-nothing-else-1   as AliasesNothingElse   store {filesystem}
```

## § 5 Compare, the two-tops way (mechanized)

```alloy
sig Site { verb: one Verb, arg: one Key, writes: set Key, reads: set Key }
fun top[x, A: Key]: one Key { x.*parent & parent.A }
pred separated[S: set Decl, x, y: Key] {
   some A: x.^parent & y.^parent | no (x.^parent & y.^parent - A.*parent) and
   let tx = top[x, A], ty = top[y, A] |
      tx.scheme = ty.scheme and tx.value != ty.value
      and (some d: UniqueName & S | d.on = tx.scheme)
      and all s: (x.^parent + y.^parent) - A.*parent | some d: AliasesNothingElse & S | d.store = s
}
fun answer[S: set Decl, q: Query]: one Ans { separated[S, q.write, q.read] implies DISJOINT else UNKNOWN }
pred wrong[S: set Decl, q: Query] { answer[S, q] = DISJOINT and q.write.reaches = q.read.reaches }
fun restsOn[S: set Decl, q: Query]: set Decl { { d: S | answer[S - d, q] != answer[S, q] } }
```

The query's two keys are the resolved keys, each path followed through its yields to the
inode scheme. Which inode each path reaches is not this section's to say; it is a measure.

## § 6 Who may say what (normative, not mechanized)

```normative
A claim is made by the seat that can know it. Whether a filesystem exposes its inodes
elsewhere is the filesystem describer's knowledge, never the file describer's. The engine
chains and meets; it originates no claim. Every survival names the claims it rested on and
no others.
```

The last sentence is mechanized in `generic` as `attributionHonest`, `attributionSufficient`,
and `attributionMinimal`. The first two sentences are not: the lint checks that a claim's
speaker `describes` the class of the claim's subject, which catches
`simon-ext4-exposes-nothing-else-1` being spoken by `tessa`, but whether a seat *can* know a
thing stays this fence's, attributed to the human who wrote it.

## § 8 The same books under less speech, and under other speech (mechanized by the books)

```sh
#> book siblings-without-simon
#> loads tessa carl world
#> same-lines-as siblings

#} {cmd-chmod} {mode-g+w} {c-path}                  #=> guard
chmod g+w /srv/a/other
```

Removing one true claim moves `elide` to `guard` and never to a wrong answer. That is
`monotoneInSpeech` on this book, and the danger column says the removed claim was the one
whose falsity would have been a wrong `DISJOINT`.

```claims
claim tessa-single-entry-path-is-a-way-of-writing-1   tessa  derived  {path} -> {entry} in {directory}, declining when the {inode} that {entry} names has another {entry}  ; danger wDISJ ; "a path scheme that admits only spellings whose inode has one entry; under it a path names a file uniquely"
```

```filed
filed tessa-single-entry-path-is-a-way-of-writing-1   as Yields      from {path} to {entry}
filed tessa-single-entry-path-is-a-way-of-writing-1   as UniqueName  on {path}
```

```sh
#> book two-paths-one-inode-under-single-entry-scheme
#> loads tessa simon carl world
#> replaces tessa-path-is-a-way-of-writing-1 tessa-entries-may-share-an-inode-1 with tessa-single-entry-path-is-a-way-of-writing-1
#> same-lines-as two-paths-one-inode

#} {cmd-chmod} {mode-g+w} {b-path}                  #=> guard
chmod g+w /srv/b/shared
```

Under the stricter scheme the measure contradicts the scheme's precondition, the derived
claim declines for both paths, no key resolves, and the site guards with nothing attributed.
No statement was false; the scheme said less than the world needed.

```sh
#> book siblings-under-single-entry-scheme
#> loads tessa simon carl world
#> replaces tessa-path-is-a-way-of-writing-1 tessa-entries-may-share-an-inode-1 with tessa-single-entry-path-is-a-way-of-writing-1
#> same-lines-as siblings

#} {cmd-chmod} {mode-g+w} {c-path}                  #=> elide by tessa-single-entry-path-is-a-way-of-writing-1 simon-ext4-exposes-nothing-else-1 carl-chmod-writes-its-path-1
chmod g+w /srv/a/other
```

Same book, same outcome, a different attribution set: separation is now concluded one
level higher, at the path scheme, and `tessa-file-has-one-inode-1` is no longer load-bearing.
The lock records both sets; the diff between them is what the stricter scheme buys.
