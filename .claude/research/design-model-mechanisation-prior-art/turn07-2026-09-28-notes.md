## Findings

- The prior conductor wrote the skill from turn06 alone; turn05's field findings that the book does
  not state were absent from it and are now folded in: the predicate-named `run` that never applies
  the predicate, `init; always next`, `until` asserting its right side, equality of two empties, the
  pre-6 `sig Time` idiom, `some` not `one` in a transitions fact.
- A command whose block is non-empty is a label plus that block for `run` as for `check`; the
  skill's grep-catch (empty block sharing an assertion's name) misses the `run pred { extra }` form,
  which cost a practitioner a week [B-alloy-discourse-run-label-shadows-pred-2020].
- Stutter is not always mandatory: when the transition relation is total by design, adding it admits
  idle traces and makes every liveness claim need fairness; the one peer skill with an evaluation
  built an eval case around exactly that defect [C-lablambworks-alloy6-evals-2026]:29;
  [C-lablambworks-alloy6-skill-2026]:68. The book's own wording is a recommendation, not a rule.
- `let` is substitution, so a `let`-bound value shifts with the temporal operator it sits under;
  nothing freezes a value across `eventually` [C-adzerk-alloy-more-skill-2026]:1041-1047. Adjacent
  states compare by prime; earlier states by `before` under a future operator.
- Two independent agents repairing a real memory model rebuilt a relation from primitives beside the
  model's own named helper and both missed the accepted fix
  [C-lablambworks-alloy6-maintenance-reference-2026]:29-33,63-65. The counter-habit is an inventory
  of the model's `fun` and `pred` definitions before composing, and an equivalence check before
  replacing one.
- The mutation operators of MuAlloy are the concrete menu for the skill's kill step, and each
  mutant is judged by `check { original <=> mutant }` at scope, which is the unit-level mechanism
  for "a reword moves nothing" [B-wang-mualloy-mutation-testing-2018]:p2-3.
- An Alloy test is a valuation plus a command; a rejection test is `run { valuation and not pred }`,
  which is satisfiable when the valuation is rejected and so cannot pass by scope starvation; a
  partial valuation stands for every completion; coverage per construct includes the size-zero
  case [B-sullivan-aunit-test-automation-2018]:p2. Size zero is the empty-set hole the identity
  model's three crosscheck rounds kept missing.
- With-skill versus no-skill, measured once: 28/28 against 27/28 on quality and roughly a fifth fewer
  tokens [C-lablambworks-alloy6-evals-2026]:5,53. A skill buys efficiency and the rare trap, not
  competence; the Analyzer loop is the competence.
- Tooling: the repository's runner (`spike/verify/alloy/AlloyRunner.java`, the `only` filter at
  lines 98 and 122) prints zero rows when `--command` names nothing and, as far as the code shows,
  exits clean; the same fail-open the peer skill documents for the upstream `-c` selector
  [C-lablambworks-alloy6-debugging-reference-2026]:69. Not fixed this turn.
- `examples.md` was transcribed from the book's text and never executed. Reading found one internal
  inconsistency: the negative instance with a shared name had no fact to reject it. Repaired by
  adding the book's uniqueness fact; the file still owes a run against the pinned jar.
