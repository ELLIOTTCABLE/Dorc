# turn 9 — 2026-08-14 15:27:48 CDT

Scope of this turn: external prior art for *mechanically linking* a partial formal model to a
reviewable prose surface. Gather-and-grade only; no synthesis pass, no recommendation.

## Findings

- The exact proposed shape — normative prose laid out clause-by-clause beside per-clause modelling
  annotations, built expressly so the model can be resynchronised when the text moves — has been
  built once, published at CCS, and then abandoned mid-standard. [B-tls13tamarin-artifact-2018]
  froze at draft 21 of 28; its authors' own claim that they could "immediately track where the model
  should be changed" [A-cremers-tls13-symbolic-analysis-2017] was never exercised against the
  finished RFC. This is the single most direct precedent and it is a negative one.
- The strongest counter-evidence to the census-gate idea itself: a one-to-one pairing can be fully
  green and assert nothing. Four merged Kani contracts in the Rust std verification effort survive
  mutants that gut the function entirely, because the postconditions assert only what the return
  type already guarantees [B-verify-rust-std-tautological-postconditions-2026]. Name-pairing proves
  a theorem *exists*, never that it *says* anything.
- The same source supplies the mechanism by which an empty formal statement propagates: the author
  copied the vacuous pattern himself because it read as house style. That is a direct hit on the
  colocation rationale — putting prose and formal side by side makes the *pattern* legible to
  imitators, which cuts both ways. [B-verify-rust-std-tautological-postconditions-2026]
- There is a third authority direction the (b) framing misses, and it is the one industrial success:
  neither prose-authoritative nor formal-authoritative, but *both generated from one master source*.
  Arm rebuilt its specification process so the machine-readable spec and the published manual come
  from the same materials [A-reid-trustworthy-arm-specs-2016]. Where the two disagreed, the formal
  side won and a bug was filed against the prose [A-reid-who-guards-guards-2017].
- The control case for what happens without that: RISC-V keeps four artifacts in four repositories
  with no generation relationship, so the same rule is written four times and only testing and
  review check they agree [B-reid-improve-riscv-specification-2024]. Its maintainers still name
  prose/formal reconciliation as an open problem, and the one place formal fragments were spliced
  into the manual has already gone stale [A-sail-riscv-model-state-2025].
- Arm also did the prose half of the proposed shape: it restructured its English into labelled
  normative ("R") and informative ("I") rules to make them individually checkable
  [A-reid-who-guards-guards-2017]. That is the closest industrial precedent for English rule-slugs
  as first-class addressable objects.
- Reid, who has the most reason to believe in formal specs, argues the formal artifact *structurally
  cannot* carry architectural intent, so prose is not merely a review surface — it holds content the
  formal side cannot express [B-reid-natural-language-specs-useful-2017]. He also predicted in 2017
  that any dual-source rule scheme would inevitably drift.
- A shipping, non-academic instance of the census gate exists and is not from the proof world:
  AWS's duvet quotes normative text verbatim into source comments, types each citation
  (implementation / test / implication / exception / todo), and reports coverage against the
  document [B-duvet-annotations-guide-2025]. The `exception` and `todo` types are the notable design
  move — the gate models *deliberate non-coverage* rather than demanding totality.
- Alectryon supplies the drift-detection primitive in the cleanest form found: check the recorded
  prover output into version control, so a change that silently alters an embedded example surfaces
  as a reviewable diff instead of vanishing [B-alectryon-untangling-intro-2020]. Its author names
  the exact failure it prevents — output "will silently change, with no error or warning".
- The oldest prior art is Isabelle's antiquotations (1990s-era, still shipping): prose blocks embed
  references to formal entities that are checked at document-build time, so a renamed or restated
  theorem breaks the build [B-isabelle-documents-antiquotations-2024]. The same document carries the
  warning that matters most for a literate design — suppressing parts of the formal text can
  "invalidate the visible text", i.e. a literate unit can lie by omission while still compiling.
- Lean's own ecosystem is the closest live analogue and it works: every example in the Lean
  reference manual is elaborated at build time, the prose carries tests that fail when the language
  moves under it, and syntax descriptions are checked against the actual parser
  [B-lean-reference-manual-readme-2026]. Verso's cross-reference database makes a removed target an
  error rather than a dead link [B-verso-readme-2026].
- Rust's std-contracts effort is the nearest peer and it is explicitly prose-authoritative:
  contracts are meant to *capture* the English safety conditions already in doc comments
  [A-rust-goal-std-contracts-2025], [A-rust-mcp-759-contracts-2024]. Critically, **no source in that
  slice describes any mechanism for checking a contract still says what its English says** — the
  only correspondence check found anywhere is a human review-checklist item
  [A-verify-rust-std-general-rules-2024].
- Scale reality-check on census gates: after a funded multi-year push, contracts cover ~4% of core's
  unsafe surface and ~1.4% of std's, no safety bugs have been found, and the coverage-tracking
  scripts are conceded to be heuristics that say nothing about sufficiency
  [A-leblanc-lam-verify-std-lessons-2025].
- Rust's `// SAFETY:` convention — the largest deployed prose-per-obligation gate — turns out to be
  *policy plus review*, not machinery: the lint exists but sits in clippy's opt-in `restriction`
  tier [B-clippy-undocumented-unsafe-blocks-2026], [B-rust-std-safety-comments-policy-2026].
- The certification world does not mechanise this either. Under DO-333 the requirement-to-formal-
  property link is a *human review objective* ("conservative representation"); what is mechanised is
  proof between formal artifacts, plus an ablation trick — delete a requirement, show the system
  proof fails [A-nasa-do333-case-studies-2014]. That ablation is directly stealable as a
  teeth-checking gate.
- Traceability rot is structurally predicted and empirically measured, not incidental
  [A-gotel-traceability-problem-1994], [A-fucci-traceability-awry-2022]; but the honest reading is
  "valuable and expensive", not "theatre" — a controlled experiment measured real speed and
  correctness gains from having the links [B-mader-egyed-traceability-benefit-2015].
- Counter-thesis, and it is well-evidenced: the model *need not* mirror the prose at all. McMillan
  and Zuck deliberately wrote an extensional model (wire-visible behaviour) against an intentional
  RFC (internal implementation), and argue the two are complementary rather than paired
  [A-mcmillan-zuck-quic-spec-2019]. Under that view a 1:1 slug-to-theorem census is a category error.
- The one IETF draft that argued for colocation argued *against* side-by-side syncing on exactly the
  drift grounds — a parallel machine-readable structure "creates the potential for inconsistency",
  so the formal layer should live *inside* the canonical document
  [C-mcquistin-augmented-ascii-diagrams-2022]. It expired unadopted. Both integration strategies
  have now failed to take, which is useful negative information about the state of the art.
- Partiality is defensible on the record: a partial spec still generates tests and still pays,
  and a well-chosen specification language is *better* than an implementation language at "being
  perfectly clear about what it is not saying" [A-cacm-village-protocol-specs-2025].
- Industrial reviewability evidence: AWS found engineers could not become productive in the
  mathematical notation, and moved toward a state-machine language plus runtime trace-checking to
  connect design-time specs to shipped code [A-cacm-aws-systems-correctness-2025]. Relevant to a
  project whose owner is explicitly not proof-literate.
- SPARK is the one place contracts are *both* the proof obligation and a runtime check — the
  executable-interrogation property, shipping [B-spark-reference-manual-intro-2026]. Its own manual
  concedes that when an assertion fails, the contract is wrong about as often as the code is; and an
  unsound contract can silently corrupt everything proved against it
  [C-dross-function-contracts-spark-2014].
- Not re-read this turn, but already in the manifest and directly relevant to the Lean-model half:
  [A-cedar-verification-guided-development-2024] and [A-cedar-rfc-port-formalization-lean-2023].
