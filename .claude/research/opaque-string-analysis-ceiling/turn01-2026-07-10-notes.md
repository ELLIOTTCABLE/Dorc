## Findings

- ceiling-fd1: the wrapper/opaque-string topic exists in the corpus ONLY as deferral
  records; no design round has ever run on it. It is seam-reserved in five places but
  designed in zero.
- ceiling-fd2: the corpus blurs two structurally-distinct sub-shapes: argv-passthrough
  wrappers (`sudo CMD ARGS…` — nested argv already word-split) vs string-carrying bounces
  (`sh -c 'STR'`, `su -c 'STR'`, `ssh host 'STR'` — payload is ONE word needing value-plane
  resolution then nested re-parse). The analyzer machinery for the second's cousin
  (`$(…)` cmdsub) already parses nested bodies to real sub-ASTs, but the VALUE plane
  collapses any dynamic string to ⊤, cause-erased and silent (notes/219 q-1).
- ceiling-fd3: the built spike has ZERO wrapper modeling — `sudo`/`ssh`/`sh -c` are
  ordinary un-oracled commands ⇒ Opaque ⇒ poison walls. Grep-confirmed: the only `sh -c`
  mentions in spike/crates are leaf-seam doc-comments ("never one opaque `sh -c`" — Dorc's
  own execution model refuses the very shape users write; core/src/lib.rs:49,
  plan/src/lib.rs:647).
- ceiling-fd4: field evidence already ranks this the #1 capability gap: 24R
  flag-sudo-weight ("both halves independently promote wrapper-opacity to the #1 capability
  gap"); r25's `su - postgres -c '…'` = "permanent opaque-wrapper wall" on the standard
  Debian idiom; `case "$(hostname)"` walled the ENTIRE r25 book (dq-cmdsub-inner-nonleaf);
  USER_STORY concedes "sudo lines still wall (honestly)".
- ceiling-fd5: general shell-analysis prior-art is ALREADY well-covered in-corpus
  (plans/055 reference architecture: MOD/IFDS/TAJS, eval→⊤ as the formal unsafe boundary,
  eval ≈ 9%/4% corpus rate; vendored clones of CoLiS/morbig/morsmall/smoosh/oils/
  shellcheck/mvdan-sh; notes/092 flow-typing/tainting). What has NEVER been surveyed:
  (a) string abstract-interpretation / string-domain literature (the JSA lineage,
  eval-handling in JS/PHP analyzers), (b) wrapper-decomposition practice in real shell
  tooling (does ShellCheck peel `sudo`? resholve/binlore's exec-wrapper lore; PaSh's
  per-command annotation model for `xargs`-likes), (c) the injection-detection taint
  literature (the *inverse* problem — strings flowing INTO `sh -c` — whose
  string-reconstruction machinery is exactly "dataflow feeds decomposition").
- ceiling-fd6: the standing design constraints any ceiling must respect: the welded
  must-handle set (const-prop, interprocedural, variables, heredocs; the ONE punt is
  `eval` — 23O:305, 17N:127); kCONTEXT redline (context-sensitivity only where the domain
  stays flat — and wrapper-context is literally a context axis, so the ceiling round
  collides with a high-lock-in knob); kFAIL welds (probe never mutates / apply never
  skips); the oracle-contract shape (role-sibling function families; silence licenses
  nothing).
- ceiling-fd7: 17N §7 named the shape once, precisely, then deferred it: wrappers run "a
  *nested, analyzable* command in a named **context** that is a *separate per-kind
  namespace* (the same `apt-get install nginx` is a different cell on host-A vs host-B vs
  inside a container) — and `ssh`/`docker exec` *are Dorc's own execution model*." The
  wrapper-context dq = whether execution-context becomes a first-class kind, designed once
  across analyzer + transport (kCOMMS).
- ceiling-fd8: 219's q-3 "prize" (Query-shaped `$()` — value-carrying stdout capture) was
  designed-not-built, with three named re-architecture costs (no stdout wire; non-leaf→leaf
  promotion; record grammar for arbitrary text). "Dataflow feeds opaque-blob decomposition"
  is that prize generalized: argv-position strings instead of stdout-capture, nested
  re-parse instead of value carriage. Same seams, same costs, plus parsing.

## Proposed decomposition (for human adjudication before turn 2)

- ceiling-q1 (taxonomy): enumerate the bounce-command state-space from real idioms —
  argv-passthrough (sudo, env, timeout, nice, flock, chroot…) vs string-carrying
  (sh -c, su -c, ssh, xargs sh -c, find -exec sh -c…) vs stream-carrying (`curl | sh`,
  heredoc-into-ssh) vs capture-position (`$(…)`, 219's ground). Which cells are
  oracle-describable at all; which need engine machinery; which are ⊤-forever.
- ceiling-q2 (prior-art, analysis): string abstract domains + eval-handling — JSA lineage,
  TAJS's eval story, PHP taint/string analyzers, injection-detection literature;
  CoLiS's actual handling of wrappers in Debian maintainer scripts (vendored, readable
  offline). What precision did each buy, at what domain cost (kCONTEXT collision).
- ceiling-q3 (prior-art, practice): what shipping shell tools DO — ShellCheck's wrapper
  peeling (vendored), resholve/binlore exec-lore, PaSh annotations, mvdan-sh/oils
  facilities. The "annotation-by-narrowing" fit: how much decomposition can ride the
  oracle contract (a sudo oracle spelling "peel me") vs engine-native knowledge.
- ceiling-q4 (the dataflow feed): how far const-prop/partial-eval carries argv-string
  reconstruction in OUR dialect (must-handle set: variables, heredocs, interproc) before
  ⊤; where the 219 value-plane needs cause-tags/recipes upgraded to feed a nested parse;
  the leaf-promotion + provenance costs (offset-corrected spans, an-leaf-text).
- ceiling-q5 (the ceiling statement): synthesize into a defensible ceiling per taxonomy
  cell — engine-provable / oracle-carried / ⊤-forever — with the exclusion-check applied
  (probe↔apply, admin↔engineer, reliable↔unreliable oracles, both propagation directions).
