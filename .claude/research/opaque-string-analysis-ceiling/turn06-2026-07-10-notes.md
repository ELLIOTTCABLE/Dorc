## Chain-of-attribution (the correctness × monotonicity interaction, distilled for the
eventual ceiling report)

Every cross-context elision cites a CHAIN: wrapper-author's peel+axes → kind-owner's
per-axis declaration → tool-author's vouch → the probe measurement. Each rung of the
enhancement ladder adds exactly one named link and unlocks exactly the value that link
licenses; silence at any link is that link's floor (wall/guard/run), never a crash and
never a borrowed assumption. Monotone value, monotone NAMED liability, zero unattributed
risk growth — the 233-family posture extended one axis.

## The attribution razor (human-MINTED; candidate for the durable law registry)

razor-attributable-line (verbatim-ish): "are all the failures introduced by this mode
*directly and singlely attributable*, dorc-why style, to a *particular* line of code
from a *particular* human?" — the flag-decision razor, superseding the earlier
pathology-scope wording ("nobody made a mistake, can only exist in the union of correct
decisions by mutually-unaware-parties"). What the flagged touches() class lacks is
exactly this: an omission failure is attributable to a FUNCTION but no particular line
SAYS the false thing. Positive mis-assertions are pointable; omissions are not.
Scope ruling: evolution-skew (selllimit3 below) is OUT-OF-SCOPE for this round —
general, known, unchanged by this work; nearest answers MH2 / binary-sha-matching
oracles.

## The invariance-tier argument (against the standing dual-gate law)

Standing law: "introducing additional potential-underexecution" sits behind a DUAL gate —
(gate-1) an oracle-author act, opt-in-by-creation where the creation has no value when
opted-out; (gate-2) an admin act (the flag); lean = ONE unified flag across mechanisms.

- opaques6-finding12-gate1-uncontested (+SURE): gate-1 is satisfied by invariance
  declarations identically to touches() — authoring `invariant` has no value except
  enabling cross-context identification, so creation IS the opt-in. The dispute is
  gate-2 only.
- opaques6-finding13-perimeter-by-outcome (the load-bearing reformulation, ~SUSPECT
  strong): unify the flag by GATED OUTCOME, not claim-type — the flag gates SURVIVAL
  (keeping an elision past a RUNNING mutation on traveled claims), whatever claim-types
  feed it. Invariance-fed survival (drifted day, wall runs, cross-context elision kept)
  still pays the flag; steady-state invariance-elision (no runner between probe and
  site) is vouch-tier. "Unflag this mechanism" ≠ "this claim-type never flagged."
- opaques6-sell1-kind-subscription: invariance fails the old pathology-scope test for
  the flagged class. A tool-oracle binding facts to a kind is in an AWARE, chosen
  relationship with that kind's published definition (17N Part II;
  an-cross-oracle-coherence is already an unflagged expectation); the kind's
  context-topology is part of what subscribers subscribe to. A wrong invariance is a
  MISTAKE (wrong definition or mis-binding), locally attributable within an aware
  relationship — the vouch-class, not the union-of-unaware-parties class.
- opaques6-sell2-no-bridged-mutation: the flagged class's risk anatomy is an open-world
  NEGATIVE about a running black-box ("nothing else was touched") — the frame problem,
  unfalsifiable. Steady-state invariance-elision bridges no mutation: measurement +
  coordinate-identity at one site; the probe→apply window is the same accepted whyrun2
  residual every unflagged elision has. Any actually-running wall re-invokes the flag
  unchanged (finding13).
- opaques6-sell3-falsifiability-class: footprint completeness cannot be tested
  (enumerate what a binary does NOT touch); invariance CAN — differential: same probe
  body, two users, mutate-as-A/probe-as-B, container fixtures (kVERIFY-calibrate
  machinery). Stdlib battle-testing can actually discharge invariance claims; it can
  never discharge footprint completeness. Testable-claim classes have gone unflagged
  historically (the vouch).
- opaques6-sell4-guard-incoherence (+SURE, the sharpest concrete): the flagship admin
  idiom `dpkg -s nginx || sudo apt-get install -y nginx` — the admin's OWN CODE asserts
  the cross-boundary identification (unprivileged read decides the privileged
  mutation). Its sudo-free twin lifts unflagged at USER_STORY stage 1. Flag-gating
  invariance means the word "sudo" toggles a trust-flag requirement on IDENTICAL
  authored semantics — the delta gated is a fact about dpkg's state topology, not any
  claim the admin composed. Incoherent. RETRACTION recorded: the bare
  rul-admin-typed-the-boundary form ("typing sudo = consent to elision") is
  intent-inflation and is walked back — typing sudo expresses "needs root," nothing
  more; the defensible core is the GUARD form, where the identification is
  admin-authored in sh.
- opaques6-sell5-flag-dilution: the flag's value is its perimeter (USER_STORY: typed by
  the person who owns the consequences; already "marketing at best, theatre at worst").
  Gating everyday sudo value guarantees book-top boilerplate flags ⇒ the flag stops
  carrying information exactly where it matters (survival). NOT flagging steady-state
  invariance PROTECTS the unified flag's meaning.
- opaques6-selllimit1-bare-lines: sell4 covers admin-guarded sites only; bare
  `sudo apt-get update` rests on sell1/2/3/5. Weaker there.
- opaques6-selllimit2-kinds-as-contracts-unbuilt: sell1 leans on kind-subscription being
  real; today it is design-intent + a seam (an-cross-oracle-coherence), not machinery.
  If kinds degrade to grab-bags in practice, sell1 weakens materially. [Worked further
  in finding15/finding18.]
- opaques6-selllimit3-evolution-skew: mutual-unawareness CAN be reconstructed over TIME
  (kind declared invariant in year 1; a tool grows a per-user mode in year 3 — the pip
  --user shape). The same skew afflicts the unflagged VOUCH; the design's answer there
  is tethering (MH2, rul24-divergence-is-the-game), not flags. Ruled out-of-scope for
  this round (see razor block).

## Worst-case failure anatomy under the razor

- opaques6-finding14-worstcase-two-party: the canonical worst case needs the kind owned
  SEPARATELY from the binder (same-author cases collapse trivially): base-library
  declares sm.dorc.Package user=INVARIANT (true for the dpkg world); a third-party pipx
  oracle binds pipx-installed apps (which live in ~/.local) to sm.dorc.Package. Probe as
  alice reads converged (her ~/.local view); invariance identifies her cell with root's;
  `sudo pipx install foo` elides; root lacked foo. Silent under-execute. With a CRISP
  contract (context-topology machine-read on the kind), the why-chain adjudicates: the
  binding violated the kind's declared topology ⇒ culprit = the pipx oracle's emission
  line. Pointable, single, human. Razor PASSES.
- opaques6-finding15-unattributable-construction (+SURE this is the real one): the SAME
  failure with a FUZZY kind contract (no machine-read topology; semantics in prose or
  nowhere) is UNADJUDICABLE — declaration-line and binding-line are both defensible, the
  wrongness lives only in their union, no particular human line says the false thing.
  Razor FAILS. ⇒ The no-flag position is CONDITIONAL: steady-state invariance-elision is
  vouch-tier IF AND ONLY IF context-topology is a machine-adjudicable part of the kind
  contract. If we cannot or will not build that adjudicability, the razor itself says
  flag it.
- opaques6-finding16-axes-omission-relocated: wrapper axes-declarations are
  at-most-shaped (an un-declared moved axis = the touches()-omission analog) UNLESS the
  axis vocabulary is CLOSED and declarations are per-axis TOTAL. The omission risk
  relocates to the VOCABULARY itself (context dimensions reality has that the engine's
  set lacks). Mitigation: the wrapper contract carries an expressibility clause
  ("declare axes only if your tool's context effects are fully expressible in the
  vocabulary; else decline-to-peel") — converting known-inexpressible cases into
  pointable mis-declarations. RESIDUAL unattributable: vocabulary-gap × author-ignorance
  — nobody's line; Dorc's horizon per IMPLEMENTATION's
  errors-we-can't-attribute-are-our-fault. [REFINED by opaques7-finding2: totality is a
  value incentive, not a soundness requirement — per-axis silence = unknown-move (⊤),
  safe.]
- opaques6-finding17-hardcode-is-worse-under-razor (+SURE): hardcoding sudo does NOT
  avoid the failure class — a hardcoded sudo-with-stdlib-invariances hits the identical
  pipx/vocabulary-gap failures — it removes the ATTRIBUTION: every assumption becomes
  engine-owned, no human line exists to point at, the entire surface lands in the
  our-fault horizon. The algebra strictly improves the razor position: it converts most
  of the hardcode's unattributable surface into pointable declaration lines, leaving
  only the thinner vocabulary-gap residual — which the hardcode also has, in fatter
  form.
- opaques6-finding18-selllimit2-payoff-map (the adjudicability build-list): (1)
  context-topology as first-class MINTED declaration syntax on the kind — the
  declaration-syntax lean is exactly what makes the contract machine-adjudicable, so the
  syntax lean and the no-flag position are load-bearing for each other; (2) binding-side
  smell lints (probe body reads user-scoped locations while binding to a user-invariant
  kind ⇒ warn); (3) differential discharge in stdlib CI (mutate-as-A / probe-as-B, per
  kind); (4) the why-report adjudication rule (trace names declaration + binding; the
  contract clause decides which link broke). Bite is deferred, not absent: private
  per-oracle kinds collapse to single-author; shared kinds are stdlib-owned and
  battle-tested initially; the adjudicability machinery must land BEFORE kinds go
  community-shared.
