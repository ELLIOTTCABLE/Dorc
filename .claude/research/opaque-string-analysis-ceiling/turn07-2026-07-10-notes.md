## The adjudication rubric + pre-registered stakes

- (a) COORDINATE-RELEVANT — same command line, different persistent cell. The dangerous
  class; the closeability question is about THIS class only.
- (b) EVALUATION-ENVIRONMENT — changes value resolution/expansion/binary-lookup, not
  cell identity (rides opaques5-finding2 component 1).
- (c) EFFECT-PARAMETER — same cell, different written value/metadata (umask-shaped;
  surfaces as ordinary divergence at probe time, not as mis-identification).
- (d) BEHAVIORAL/PERF-ONLY. (e) PARTIALITY (dissolved per ruling-partiality-dissolved).
Stakes, stated before the data landed: if class-(a) is bounded + slow-moving +
standards-enumerated ⇒ closed-vocabulary stands. If open-ended ⇒ the closed set dies the
way kinds died; fallback = bounded-open (core closed set + expressibility clause forcing
decline-to-peel outside it — re-widens walls, never mints unsoundness). Either way the
razor governs: vocabulary gaps are Dorc's-fault horizon, not attributable lines.

## The kind-minting cliff concern, analyzed

- opaques7-finding1-no-totality-at-mint (+SURE, the anti-cliff design rule): the feared
  cliff (per-kind axis DEFAULTS as a form of at-most-ness — "I declared fs-root
  topology, wasn't thinking about the rest" ⇒ dislocated other-author under-execution)
  exists ONLY if kind-minting requires total per-axis answers, or if undeclared axes
  default to anything that IDENTIFIES. Neither is needed: kind-side context declarations
  are per-axis OPTIONAL; silence on an axis = the may-alias floor (no identification, no
  disjointness — walls, safe). Dislocated under-execution requires a POSITIVE false
  declaration — a pointable line, razor-passing. The engine's per-kind defaults are not
  at-most-shaped: the floor claims nothing.
- opaques7-finding2-wrapper-silence-unknown-move (refines opaques6-finding16): totality
  on WRAPPER declarations is likewise not a soundness requirement if per-axis silence
  defaults to UNKNOWN-MOVE (⊤: may move this axis arbitrarily) — safe,
  value-destroying. Totality becomes a value incentive, not a contract clause; the
  expressibility clause remains only for the vocabulary-gap case.
- opaques7-finding3-kind-axis-set-is-smaller (+SURE): the kind-topology surface excludes
  ρ-side dimensions — env is evaluation-environment, never a kind-topology question; a
  kind cannot be "env-sensitive" in the coordinate algebra. Kind-side axes ⊆ {user,
  fs-root, host(someday-never)}.
- opaques7-finding4-gradual-story-restated: with finding1/2 the enhancement curve at
  kind-mint has NO cliff: mint bare kind (all-floor, today's exact behavior) → declare
  one axis when you know it → each subsequent axis likewise. Fine-grained
  per-axis-per-kind monotonicity; partial declarations yield partial value and full
  soundness.

## The evaluation environment (ρ) — terminology + mechanics

ruling-term-environment: the concept formerly "seed" is the **environment** (ρ) — the
nested region's evaluation environment, standard operational-semantics sense; sh's
env-VARS are one component of ρ alongside positionals and cwd. Historical seed-named
slugs stand; forward usage is ρ/environment.

- opaques7-finding10-seed-definition (+SURE): ρ = the var-state {env-vars, positionals,
  cwd} under which nested code and its oracles EVALUATE, with two consumers: (1) the
  nested command/payload's own value-plane (expansion, argv resolution, branch
  decisions); (2) the nested tool's ORACLE BODIES (is_converged/touches traced against
  the installed ρ). Irreducibility to the coordinate algebra is a stage-difference: ρ
  acts at EVALUATION time (VarState → VarState, before any cell is named — an
  interpreter environment); the coordinate algebra acts at COMPARISON time (Cell ↔
  Cell, after names are computed — an equivalence on the store). Pipeline: ρ → values →
  argv/paths → cell names → (only then) the algebra. finding8 rides this: selector-vars
  mean ρ-precision BUYS coordinate-precision, but through the ordinary value plane —
  never as a separate trust surface.
- opaques7-finding11-expansion-timing (+SURE): the demonstration pair —
  `sudo cp ./motd.txt ~/greeting.txt` (tilde expands in the OUTER shell, alice's HOME,
  before sudo exists: /home/alice/greeting.txt, written as root) vs
  `sudo sh -c 'cp ./motd.txt ~/greeting.txt'` (payload re-enters expansion INSIDE the
  context: HOME=/root ⇒ /root/greeting.txt). Same-looking command, different cell,
  purely from WHERE expansion happens relative to the boundary
  ([A-greenberg-smoosh-2020]'s read/eval-loop-parameterized-by-live-env, concrete).
  Consequence: ρ is the PEEL'S SOUNDNESS SUBSTRATE, not a refinement — pay-litstring
  decomposition of even fully-LITERAL payloads is unsound without evaluating them under
  the installed ρ.
- opaques7-finding12-probe-closure (+SURE mechanics; feeds the eventual build spec): the
  analyzer TRACES oracle bodies under ρ, but shipped PROBES run in the probe user's real
  environment — an analyzer-model/probe-runtime divergence vector. Fix shape: shipped
  probe invocations are CLOSED over the ρ assumptions they were analyzed under; a
  ⊤-dependency is unpinnable ⇒ unshippable ⇒ can't-say ⇒ run. kFAIL-withhold unaffected
  (closure is read-only). Probe-outside (opaques5-finding3) gains a rider: invariance
  licenses reading the cell from outside; the CHECK's dependencies must additionally be
  closed or var-free. [SUPERSEDED-IN-MECHANISM by finding20: closure is whole-ρ
  replication, not per-variable pinning.]
- opaques7-finding13-seed-floor-cheap (+SURE): ρ's floor is all-⊤ — sound, free, and
  value-losing only for var-DEPENDENT facts; the famous idioms
  (`sudo apt-get install -y nginx` — argv-literal) need zero env machinery. Refinements
  are per-var, per-wrapper, monotonic, statically-groundable-only (`env VAR=x` = gold:
  value in argv; sudoers env_keep / `su -` login files = host state ⇒ ⊤ absent a
  claim). Safe direction verified: a ⊤ var can only produce ⊤ words ⇒ Opaque/entity-⊤ ⇒
  runs/walls; never licenses.

## The env-enumeration question (does value under sudo require enumerating the tool's
env reads/writes?)

Wrapper-side writes INTO the child ρ (`env VAR=x` mapping its own argv into inner
env-vars) are a small pay-once wrapper-oracle class — sudo/env/su and a few others.
The live question was tool-side.

- opaques7-finding14-no-env-enumeration (+SURE; the answer is NO, via a three-lane
  division of labor, two lanes pre-existing at HEAD): (lane 1) SHELL-VISIBLE references:
  a peeled command's argv is expanded by the OUTER shell against the OUTER (known)
  environment before the wrapper runs — ρ governs ONLY payload-internal references, so
  ⊤-ρ's blast radius is PER-TEXTUAL-REFERENCE, not per-command; the entire turn-6
  walkthrough book loses ZERO value under all-⊤ ρ. (lane 2) TOOL-INTERNAL env reads
  (getenv inside apt): NEVER engine-modeled — vouch territory, definitionally; sudo-
  scrubbed env is the MOST-standard environment the famous ops tools run under. (lane 3)
  ORACLE-BODY references: probe-closure governs (finding12/finding20). Env WRITES by the
  wrapped command: free — a child cannot mutate its parent's environment; the existing
  scope-clobber machinery models stays-in-that-shell. Nothing to enumerate, ever.
- opaques7-finding15-mutator-loud-check-narrow (+SURE, the residual decomposed): the
  probe-env ≠ apply-env divergence risk splits by consumer, both halves benign-shaped:
  env-sensitivity of the MUTATOR (scrubbed http_proxy breaks apt's fetch at apply) ⇒
  the command RUNS and FAILS LOUDLY — baseline bare-sh behavior, no machinery owed.
  The silent-under-execution vector runs ONLY through CHECKS (which store does the read
  consult = the selector-variable class) ⇒ exactly what closure (finding20) and the
  oracle's ordinary decline cover.

- opaques7-finding16-no-wrapper-awareness-in-tool-oracles (+SURE, the kBURDEN headline):
  a tool oracle NEVER mentions a wrapper. No "under sudo" arms, no context conditionals,
  no wrapper names anywhere in per-TOOL functions. Composition is entirely engine-side:
  wrapper-oracle's ρ-transform + kind context declarations + the tool's ordinary
  context-FREE functions. The postgres author's HEAD-era oracle is the same file after

- opaques7-finding17-pinning-is-engine-work (+SURE, as corrected by finding19/20):
  probe-coherence closure is ENGINE-mechanical, not authored. The author's only lever is
  analyzer-precision VISIBILITY (explicit `${VAR:-default}` lets traced bodies resolve

  from author enumeration.
- opaques7-finding18-bite-map (+SURE on shape): tool classes by env-coupling: (1)
  ARGV-PURE (apt, dpkg, cp, systemctl, ufw — most of the stdlib): owe NOTHING; full
  value under sudo via kind invariance lines alone. (2) SELECTOR-VAR tools (postgres,
  git/GIT_DIR, docker/DOCKER_HOST, kube/KUBECONFIG, aws/AWS_PROFILE): the env-explicit-
  check norm is analyzer-precision hygiene (post-repair, no longer coherence-load-

  than HEAD (a `${PGDATA:-…}` body under `env PGDATA=/srv/pg` evaluates

  CREDENTIAL-GATED state (postgres peer-auth; root-only reads): no obligation exists
  because no effort helps — checks that cannot RUN from the probe context rc≥2/can't-say
  ⇒ the honest cap (opaques6-finding2); the r25 `su - postgres -c 'psql …'` line is
  class-3: correct disposition run-with-guard, no author effort demanded or wasted.
- opaques7-seed1-hermetic-probes (-GUESS, design-seed only): ship ALL checks under a
  canonical minimal environment (hermetic probe execution, kVOLATILES-exclude's rhyme) —

  Costs unexamined; park for the build spec. [Partially subsumed by finding20, which
  replicates per-site ρ rather than one canonical env.]

## KILL + REPAIR: per-visible-variable pinning was unsound

- opaques7-finding19-pinning-kill (human-caught; CORRECTION to finding17-as-first-stated,
  which stands only in its can't-pin honesty clause): per-visible-variable pinning
  cannot carry runtime coherence — the engine cannot see a black-box binary's getenv
  surface (`psql` reads PGHOST/PGPASSFILE/… with zero `$PG…` characters in the oracle
  body). A bog-standard check shipped bare consults the AMBIENT probe env while the
  wrapped site acts under the transformed env; a wrong-CONVERGED verdict then licenses a
  wrong elision whose failure is NOT attributable to any single human line (the check is
  correct under its implicit coherent-env precondition; the wrapper and kind claims are
  correct; the ENGINE composed the vouch across an env boundary the vouch never claimed
  to cross) ⇒ razor-FAIL. Visible-reference pinning would demand full env-read
  enumeration to be sound — omission-shaped, unacceptable.
- opaques7-finding20-whole-rho-replication (the repair, +SURE on mechanics): coherence
  needs no per-variable knowledge — REPLICATE THE WRAPPER'S ρ-TRANSFORM AROUND THE
  CHECK. The wrapper oracle already declares its transform (scrub + survivors;
  `env -i`; `VAR=x` sets); the engine ships the check CLOSED under that same transform
  (`env -i TERM=… PATH=… HOME=/root … <check>`), so EVERY env-read the check makes —
  visible, invisible, enumerated or not — reads act-context values. Enumeration
  requirement: dissolved. env-replication is privilege-FREE (`env -i` needs nothing),
  unlike user/fs replication. Visible-reference tracing remains useful for
  ANALYZER-precision but is no longer load-bearing for runtime coherence.
- opaques7-finding21-per-axis-probe-construction (+SURE, unifying): "run the check in
  the site's context" decomposes per-axis by replication COST: env + cwd = replicable
  free ⇒ replicate; user + fs-root = replication requires privilege we refuse ⇒
  declaration-or-cap (invariance lines / fs maps / rc≥2 honest cap); host = never. The
  env axis was never an invariance-declaration problem — it is the one axis where
  in-context probing is free.
- opaques7-finding22-strawman-disposal (the pg-wipe strawman, both directions): under
  replication the probe's environment ≈ the act environment, so ambient PGHOST-style
  contamination is scrubbed out of the probe too — coherent verdict, mechanically.
  Direction note: the "decides to RUN something dangerous" arm is baseline-equivalent —
  a wrong-diverged verdict runs the line, which bare sh does unconditionally; Dorc
  inserts no commands and never promised prevention. The Dorc-specific sin was always
  the elide direction, which the repair closes.
- opaques7-finding23-residuals-of-replication (honest, priced): (i) sudoers env_keep —
  the real act-env may keep vars the declared transform drops; the transform is
  APPROXIMATE for sudo ⇒ the wrapper-oracle's claim surface (positive, pointable,
  razor-passing; rare; -GUESS seed: derive per-host survivors from `sudo -l` at probe
  time, a touches()-style host-run arm); (ii) euid-DERIVED behavior (getpwuid,
  peer-auth) — env-replication cannot fake identity ⇒ already the class-3 cap (rc≥2,
  run-with-guard); (iii) checks that ERROR under the replicated env fail toward
  can't-say ⇒ run. All residuals fail safe or land on priced surfaces.
- kBURDEN re-audit post-repair: class-2 authors' env-explicit discipline DEMOTES from
  coherence-load-bearing to analyzer-precision-only; the enumeration burden lands on
  NOBODY; finding16's no-wrapper-awareness property SURVIVES the kill, strengthened.

## Boundary pin

- opaques7-finding24-probe-lane-only (+SURE): whole-ρ replication lives EXCLUSIVELY in
  the probe lane — the check invocations Dorc itself constructs and ships at plan time,
  never user bytes (DESIGN's collate-and-deploy; the an-wrappable-seam
  `<wrapper> -- <leaf>` indirection is the exact hook, a 077-era live constraint). The
  apply artifact is untouched: user lines verbatim, elisions comment-out, guard-tier
  unchanged. Machine-inserted GUARDS need no closure BY CONSTRUCTION: an in-sequence
  guard-check runs in the same shell stream, same environment, immediately before the
  original command — the same argument that gives in-sequence checks no staleness
  problem gives them no env-coherence problem. The single future intersection: guards at
  WRAPPED sites (parked behind the 23J seam, opaques6-finding7) would close only the
  machine-authored check-half, never the original bytes. Books gain ZERO new writing
  constraints: env-opacity in a runbook degrades value (walls, hints), never execution.
