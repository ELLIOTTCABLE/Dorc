## Proposed design pins (each needs a typed ack before it hardens)

- opaques8-pin1-licensed-code-carriers (+SURE this mirrors settled law): payload
  decomposition is LICENSED, never inferred — the head's wrapper-oracle declares
  "operand N is sh-code; operands N+1… bind $0/$@" (which-arg-is-code is argparse
  knowledge the head's author owns; resholve's INVOKABLE_SHELL list is the practice
  precedent [A-resholve-source-invocations-2025]). No declaration ⇒ HEAD behavior
  (imp-2's payload analog). The stdlib ships the sh/bash/dash carriers.
- opaques8-pin2-plain-sh-payloads (+SURE on the soundness argument): payload text parses
  as PLAIN sh — no dorcisms recognized, no dialect-marker inheritance, no binds/marks.
  Hard argument: `dorc strip` erases dorcisms from SYNTAX and never rewrites string
  interiors, so a dorcism inside a payload string would SURVIVE strip and break at
  runtime under real sh — payloads must therefore be forever-plain, or the off-ramp
  weld breaks. Rider lint: dorcism-shaped text inside a declared payload ⇒ warn
  (kWARN-rich).
- opaques8-pin3-parse-failure-degrades (+SURE): a payload the engine cannot parse
  (bashisms under `bash -c`, exotica) ⇒ payload-⊤ ⇒ SITE-LOCAL wall + a
  dq-payload-unparseable naming the site and the first offending token — NEVER a
  book-level parse error. (The book parsed fine; the degradation is per-site, exactly
  the Unevalizer/Arceri per-site-refuse posture, opaques3-finding11.)
- opaques8-pin4-whole-line-unit (~SUSPECT right for v1; THE granularity fork): the
  verdict/render unit is the wrapper LINE — the 24E §14 pipeline family (one
  span-covering unit, conservative). Inner commands become verdict-PARTICIPATING
  analysis nodes (unlike today's `$()` expansion-internal drops): the line elides only
  when every effect-bearing inner node has a reached vouch (+ carrier/wrapper
  self-vouches per opaques6-finding4); else guard-whole-line or run. Consequence:
  render-into-payload (opaques3-finding6 — rewriting WITHIN a reconstructed string,
  under quoting, byte-faithfully) is DODGED ENTIRELY in v1: no payload string is ever
  rewritten. Per-inner-command elision/guarding = that cost, parked with the
  flag-pipe-status-unit fork it rhymes with.
- opaques8-pin5-single-mechanism-analysis-time (+SURE on shape): ONE decomposition
  mechanism, at analysis time, consuming RESOLVED payload values from the value plane —
  a syntactically-literal payload is just the trivially-resolved case; a
  const-prop-resolved `CMD="…"; sh -c "$CMD"` template lands in the same lane
  (turn03 Table 1's re-homing rule). In-fixpoint splice, nesting-bounded
  ([A-unevalizer-2012]'s circularity answer, opaques3-finding14's read/eval-loop
  grounding). No separate parse-time fast path — two paths would drift.
- opaques8-pin6-ladder-and-cliffs (+SURE, closes to the round's evidence): the payload
  ladder is syntactic-literal ⊑ resolved-literal ⊑ concat-of-constants, and STOPS.
  Cliffs (⇒ payload-⊤ wall + a dq naming the exact blocker): unknown-var splice,
  cmdsub splice (`bash -c "$(curl …)"` — the USER_STORY machine.sh line stays an honest
  wall, already admin-guarded), loop-assembly, any splice in syntax position.
  Hole-parsing stays out (imp-4; unbuilt in all literature,
  opaques3-finding12-hole-parsing-unbuilt); the t2-fd17 flat refinements
  (metachar-free-single-word etc.) are NOT needed by v1 (they only matter for parsing
  AROUND splices, which v1 refuses) — deferred with the hole-parsing cell.

## Design findings

- opaques8-finding1-quote-stage-map (+SURE mechanics; the sh-vs-JS-eval wrinkle made
  concrete): a payload word's fragments partition by EXPANSION STAGE, and the
  decomposition must consume a quoting-aware recipe: double-quoted/outer fragments
  (`sh -c "restart $svc"`) are expanded by the OUTER shell — the value plane resolves
  them BEFORE the payload exists, so they arrive as VALUES (constants after const-prop,
  or ⊤ ⇒ cliff); single-quoted fragments (`sh -c 'cp x ~/y'`) are TEXT whose
  `$`-references re-expand INSIDE the child, under the installed ρ
  (opaques7-finding11-expansion-timing is the soundness anchor — same bytes, different
  cell, purely from which side of the boundary expansion happens on). Engine
  dependency named: this needs the fragment-preserving/cause-tagged ValueOf reshape
  that notes/219's tc-fork (ii) flagged and deferred — the current `Recipe::Top`
  collapse is cause-erased and fragment-destroying. Payload work is the reshape's
  first REQUIRED consumer.
- opaques8-finding2-carrier-context-record (+SURE core, edges marked): a code-carrier
  head defines a context record even UN-wrapped — it moves no coordinate axes (child
  process; the existing $()/subshell scope-clobber semantics are exactly right:
  env/var/cwd mutations inside don't escape, fs effects do), but it RESETS the
  evaluation environment in carrier-specific ways: fresh positionals (inner `$@` is
  empty unless bound — inner `$1` ≠ outer `$1`!), fresh shell-options (~SUSPect: a
  child `sh -c` does not inherit the parent's `set -e`; the 20V errexit-door analysis
  runs per-shell with a clean slate), var-inheritance only via export (inner IFS =
  default-unless-exported — ρ's per-variable modeling doing real work,
  opaques7-finding8's container point). Two edges parked with markers: bash
  exported-functions (BASH_FUNC_* env vars — bash-to-bash only) = ⊤-risk noted,
  --WONDER if worth modeling ever; `eval` is the TRANSPARENT-context degenerate cousin
  (same shell — effects DO escape; no scope-clobber) — deliberately NOT designed here,
  see opaques8-fork2.
- opaques8-finding3-value-anatomy (+SURE, calibrates expectations): where payload
  decomposition actually pays, in order of realism: (a) BOUNDED WALLS — an inner
  command with a `touches()` bounds the line's poison kind-granularly (the
  opaques6-finding8 shape) instead of the total wall the un-decomposed line casts;
  downstream elisions survive. This is the common win: the lint-taught idioms are
  single-command payloads over famous tools. (b) WHOLE-LINE ELISION — realistic
  exactly for those 1–2-command payloads when every inner node vouches (the
  `sudo sh -c 'cat >> file'` append idiom, the SC2232 `sudo sh -c 'cd /root && pwd'`
  shape). (c) SURGICAL HINTS — "line N blocked only by: inner `foo` unmodeled" (the
  first-wall-hint pattern applied inside the line). Honesty row: an un-oracled inner
  command still total-walls from its position — decomposing `su - postgres -c
  'psql …'` with no psql oracle buys hints and the su/ρ modeling only; the r25 line's
  inner psql is class-3 credential-gated regardless (opaques7-finding18), so its cap
  is run-with-guard FOREVER, and the payload machinery's contribution there is the
  honest reason string, not elision. Value is real but arrives with inner-tool oracle
  coverage, not with decomposition alone.
- opaques8-finding4-guard-conjunction (+SURE licensing, ~SUSPECT ergonomics): v1
  whole-line guards are a CONJUNCTION of the inner nodes' checks placed OUTSIDE the
  line (`( chk1 && chk2 ) || sudo sh -c '…'`). Placement licensing composes from 24S
  unchanged: a bare code-carrier moves no axes ⇒ guard-outside trivially licensed;
  under sudo∘sh-c, invariant-kind checks guard outside per the probe-outside logic
  (opaques6-finding7's posture holds: no Dorc-authored checks INSIDE any
  wrapper/payload; 23J stays parked). Checks close over bound positionals (outer-known
  values — engine substitutes) and ride §6b whole-ρ replication. Ergonomic cost
  honestly stated: multi-command payloads make long guard lines — attention-priced,
  never hidden.
- opaques8-finding5-provenance-cost (+SURE it's owed; shape ~SUSPECT): payload
  diagnostics need TWO locator tiers: (i) syntactic-literal payloads — spans map
  through the QUOTING transform (source bytes ≠ payload bytes: quote-stripping,
  escapes); an inner-node caret must render against the payload text with a
  source-span note; (ii) resolved payloads — the text is DERIVED (concat of fragments
  from multiple source spans): locators are per-fragment, the 111 locator-DAG shape
  (an-leaf-text already knows "a leaf's runnable text isn't always one [lo,hi)
  slice"). notes/219's tn-coarse-subst-provenance is the existing smaller debt;
  payloads are strictly worse and should land the general fix.
- opaques8-finding6-failure-catalog (v1 modes + plugs): (i) QUOTING-RECONSTRUCTION
  infidelity — the engine's payload value differs from what the host sh hands the
  child (escape-handling divergence): differential-testable mechanically (reconstruct
  → run under dash → compare argv; kVERIFY-calibrate machinery; add a lying-carrier /
  reconstruction-fidelity axis to the sweeps). (ii) ACCEPT-BUT-MISPARSE dialect
  divergence (our parser reads the payload differently than the host's /bin/sh) —
  same risk class as book-level parser fidelity, covered by the same differential
  harness; payload sh is empirically the plainest sh (lint-taught one-liners).
  (iii) UNQUOTED-SPLICE word-splitting ($IFS-dependent) — cliff by pin6, never
  parsed-around. (iv) WRONG CARRIER DECLARATION (declared operand-N-is-code when it's
  a filename) — a pointable wrapper-oracle line; lying-carrier sweep axis; the
  opaques6-finding3 peel cross-check generalizes (the "code" operand must PARSE and
  its head must resolve as a command — disagreement ⇒ demote-to-wall + diagnostic).
  (v) OUTER-RESIDUE on the carrier line (`sh -c 'echo x' > f` — the redirect consumes
  the whole child's stdout): ctx-outer machinery unchanged; inner nodes' consumed
  observables fold into the line unit (whole-line granularity dodges the per-inner
  consumption gap 219 q-1.d found for `$()`).
- opaques8-finding7-composition-contract (+SURE): one line can stack all three
  machineries — `echo data | sudo sh -c 'cat >> /etc/f'` = pipeline (24E, one
  span-covering unit) ∘ context (sudo: user axis + ρ-scrub) ∘ payload (sh -c: carrier
  record + nested parse). The design obligation is orthogonality: context peel and
  payload decomposition interleave by argv structure under ONE shared recursion bound
  (turn03's composition rule); ρ flows outer→wrapper-transform→carrier-reset→inner
  nodes; no machinery may special-case the others' presence. The composed case IS the
  lint-taught repair idiom, so it is v1's acceptance shape, not a stretch goal.

## opaques8-finding8-render-ladder (refines pin4 + opaques3-finding6; born from the
human's heredoc nit)

"render-into-payload" is not one cost — it is a LADDER keyed by whether the payload
bytes are human-written-and-verbatim in source:

- R0 (v1 = pin4): no payload editing, ever; whole-line unit.
- R1 (the principled follow-on): span-edits WITHIN verbatim payloads — quoted-heredoc
  bodies (bytes verbatim, spans 1:1, line-oriented) and plausibly single-quoted `-c`
  literals. Same edit vocabulary as the outer render (comment-out; quote-inert
  standins), so the authorship weld SURVIVES: the edited bytes are human-written, and
  the edits are the same moves the outer render already makes on book lines. Hazards
  real but bounded: standin quote/delimiter inertness; unquoted-heredoc outer-stage
  expansion runs on COMMENTED lines too (harmless for `$var`; cmdsub splices are
  already pin6 cliffs — the cliff protects the render); guard-INSERTS inside payloads
  stay OUT of R1 (an in-payload check executes in-child/in-context — the 23J-parked
  posture; guards remain outside, whole-line conjunction).
- R2 (the weld-shaped cell): re-serialization of RECONSTRUCTED/derived payload text —
  engine-authored sh, quoting re-embedding, razor-fail attribution. The human's
  "permanent-weld hovering" intuition lands HERE; welding R2 — not all payload
  rendering — is what keeps the weld from being relitigated by the heredoc-book cell.

- opaques8-finding9-heredoc-focus (human nit, adopted): the focus specimen is
  heredoc-script-piped-to-sh (`sudo sh <<'EOF' … EOF`) — an embedded BOOK, not a
  one-liner. It exercises: carrier licensing for stdin shapes (pay-stream's local
  cell: `sh <<EOF`, `sh -s <<EOF` + argvbind, `sh file` w/ freshness caveat;
  `curl|sh` stays ⊤); the quote-stage map (quoted heredoc = pure inner text; unquoted
  = outer-expanded template, and heredoc expansion never field-splits); REAL source
  spans (provenance nearly free — no quoting transform for the quoted form); and it
  makes R0's value-cap VISIBLE (all-or-nothing over a 20-line body ≈ wall), which is
  R1's motivation. Verdict on fork1 restated honestly: whole-line-unit covers the
  space SOUNDLY but serves it non-uniformly — `-c` one-liners well, embedded books
  poorly.
