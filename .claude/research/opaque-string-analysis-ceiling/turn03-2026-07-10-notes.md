## Exclusion-check of the grid (AGENTS four-by-two) — new findings

- opaques3-finding4-bidirectional-effects (+SURE, reverse-propagation direction): decomposition is BIDIRECTIONAL.
  Context-transform maps the world INTO the nested analysis; the nested command's effects
  must map back OUT (the inverse transform) or downstream outer lines stay walled —
  `sh -c 'apt-get install nginx'; systemctl enable nginx` only un-walls if the nested
  establishment escapes the bounce. For ctx-fsview the inverse map mints cross-context
  ALIASES (outer `/new/etc/x` ≡ inner `/etc/x`) — resolve()/CanonicalCoord was designed
  within-kind-within-context; a context-transform is a coordinate functor layered on top.
  Named design-collision, must be in the ceiling report. (Backward slicing / `dorc bump`
  comes free IF decomposition splices the payload into the same graph — t2-fd12's
  fixpoint-splice gives both directions.)
- opaques3-finding5-probe-outside-wrapper (~SUSPECT, other-phase / probe side): probe-context ≠ book-context. A probe ships
  OUTSIDE the wrapper (kFAIL-withhold; we never escalate — an-privilege-fact), so probing
  "the world as the nested command will see it" is only possible where the fact's backing
  is visible WITHOUT the transform (world-readable file vs root-only state). Ceiling for
  ctx-user-nested facts at probe time: can't-say unless outside-visible ⇒ rc≥2 honest
  path. The 23J lane-privilege seam (oracle code promoted INTO the elevated context) is
  the flip side — noted, NOT designed here. Partiality asymmetry (also other-phase):
  under ctx-partial, `touches()` at-most claims are kill-safe (still at-most under any
  prefix of execution) while establishment claims are NOT (killed apt-get may not have
  established) — partiality voids establishment, preserves footprints.
- opaques3-finding6-render-into-payload (+SURE, other-phase / apply side — NEW COST, unnamed anywhere in the corpus):
  render-into-payload. A guard for a nested command must EXECUTE inside the transformed
  context (`ssh host '( check ) || cmd'`), i.e. the render must rewrite WITHIN a
  reconstructed string payload, under sh quoting, byte-faithfully. Licensed only when
  reconstruction was faithful (pay-litstring / early pay-dynstring ladder); deep-dynamic
  payloads cannot be rewritten-into ⇒ their guard placement falls back to
  outside-the-wrapper, which only works where the backing is outside-visible (opaques3-finding5-probe-outside-wrapper) ⇒
  otherwise the cell caps at RUN. Every elide/guard verdict inside a bounce is gated on
  render feasibility, not just analysis precision.
- opaques3-finding7-lazy-admin-stdlib (+SURE, other-user): the admin-side idioms arrive Dorc-blind and lint-taught
  (t2-fd8: ShellCheck's own fixes teach `sudo sh -c`) — zero admin change is the bar, so
  ALL admin-side value rides stdlib wrapper-oracles (goal-out-of-engine). The
  engineer-side ask is the new burden: a transform-record vocabulary is a bigger spelling
  surface than a verdict-function; ceiling-q3's "annotation-by-narrowing fit" must check
  each axis for an idiomatic-sh spelling before the vocabulary is allowed to exist.
- opaques3-finding8-transform-trust-tier (+SURE, other-reliability — trust-TIER question, must surface in ceiling-q5): a
  WRONG context-transform claim (sudo oracle says env-preserved; actually scrubbed) makes
  the NESTED analysis unsound — and the nested sites belong to OTHER tools' oracles.
  Cross-author blast radius = the traveled-claim/survival trust class, NOT the vouch
  class (a vouch bites its own author's line; a transform bites someone else's). Options
  the round must present (not settle): transform claims gated like footprints
  (double-opt-in), vs conservative stdlib defaults where REFINEMENT is the risky act, vs
  per-axis safe directions. Safe directions per axis regardless: env → ⊤-vars;
  fs-view → may-touch-any-fs; partial → establishment-void.
- opaques3-finding9-lexical-not-call-context (~SUSPECT, kCONTEXT check): wrapper contexts are LEXICAL — fixed CFG positions,
