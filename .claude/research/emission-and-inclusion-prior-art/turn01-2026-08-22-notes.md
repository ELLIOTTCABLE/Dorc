## Findings

- **fnd-jumbo-died-of-renaming-not-unsoundness** — Chromium killed unity builds because the RENAMING that concatenation forces made the code worse, never because concatenation was unsound; and it considered and rejected an automated source-to-source renamer as the fix, three times. 30P's munge-everything default is the thing Chromium's users revolted against, so the attention cost of munged names is a real product risk, not a cosmetic one. [A-chromium-jumbo-removal-2019]
- **fnd-shellcheck-strips-the-dynamic-head** — a shipped shell static-analyzer resolves `source "$(dirname "${BASH_SOURCE[0]}")/utils.sh"` with NO model of `dirname`: it discards one leading dynamic segment and resolves the literal tail against a declared search path. `ask-dollar-zero-command-substitution-path` is framed as recognise-the-byte-shape versus punt; this is a third option, and it needs no allowlist. [A-shellcheck-checker-source-props-2026] [A-shellcheck-directive-wiki-2026]
- **fnd-top-level-return-is-the-universal-bailout** — the one construct 30P's paste exclusion set is built around is the same construct JS bundlers name as a hard bailout, and their fix is to WRAP the module in a function: precisely the lowering Dorc's floor refuted for sh. Independent convergence on the construct, and confirmation that the escape hatch is unavailable to us. [A-parcel-scope-hoisting-2024]
- **fnd-return-outside-a-dot-script-is-unspecified** — POSIX does not merely say a bare-pasted `return` behaves differently; it says the result is UNSPECIFIED, and names the System V (error) versus KornShell (acts like exit) split. The exclusion is settled by the standard before the atlas measures it. [A-posix-return-builtin-2018]
- **fnd-slashless-dot-operand-is-a-path-search** — a `.` operand containing no slash is resolved through PATH, not the cwd, and the cwd search was deliberately REMOVED from the standard over trojan-horse concerns. 30P's load principles resolve operands over program text, `$0`, modelled cwd and the snapshot, and say nothing about this case. [A-posix-dot-builtin-2018]
- **fnd-ansible-walked-back-textual-inclusion** — the nearest domain sibling built exactly 30P's mechanism (Module Replacer: substitute an import line with the file's contents), abandoned it, and replaced it with a real archive plus a generated loader — built that way specifically because the payload must be pipeable into the remote interpreter's stdin. Dorc refuses that loader on floor grounds and refuses the form instead; that is a genuinely unusual posture and the plan should own it as such. [A-ansible-module-architecture-2026]
- **fnd-bailout-tables-are-the-shipped-shape** — the front-lift ladder has a mature precedent: a CLOSED enumerated set of named conditions, each mapped to one of two conservative fallbacks (Prevent = keep it in its own scope; Root = start a new group), plus a user-facing flag that prints which condition fired at which module. [A-webpack-module-concatenation-2026] [A-parcel-scope-hoisting-2024]
- **fnd-renaming-is-forced-not-chosen** — rollup's lead states the invariant directly: merging modules that may bind the same name makes renaming a NECESSITY, and a merged local must never end up shadowing a global that another merged module reads. In sh every function binding is global, so this is the mechanism behind 30P's T1 condition about calls above the `.`. [B-rollup-renaming-necessity-2021] [A-parcel-scope-hoisting-2024]
- **fnd-idiom-recognition-is-legitimate-under-enumerated-preconditions** — a production compiler DOES special-case a source idiom (the include guard), under five numbered validity conditions, and switches the recognition off the moment the shape stops being literal source text, for explicitly stated cost reasons. This is the shape a count-of-two `$0` exception would take, and the precedent for pricing it. [A-gcc-cpp-guard-macros-2026]
- **fnd-shell-source-resolvers-refuse-by-default** — both shipped tools that statically resolve shell `source` default to blocking until the human declares something (`--fake source:` / `--keep source:` / `# shellcheck source=`), rather than continuing on an assumption. Dorc's point-havoc is a third posture, and the only one of the three that is sound for a tool that must not under-execute. [A-resholve-manpage-2023] [A-resholve-readme-2023] [A-shellcheck-directive-wiki-2026]
- **fnd-partly-dynamic-operands-become-sets** — the shipped answer to an operand that is part literal and part unknown is to extract the literal bound (a directory plus an extension or regex) and carry EVERY snapshot member that matches, refusing only when the literal parts bound nothing. That is 30P's own set-valued glob operand with its order-unknown withhold, reached from the computed-operand direction instead of the authored-glob direction. [A-webpack-dependency-management-2026] [A-vite-features-glob-dynamic-import-2026]
- **fnd-make-the-runtime-true** — a fourth answer to self-location under relocation, unlisted in 30P: do not rewrite the idiom and do not model it — make the runtime's self-location TRUE inside the new home, so unmodified user code resolves correctly. PyInstaller reversed its own earlier basename-only posture to get there. [A-pyinstaller-runtime-information-2026]
- **fnd-first-class-variable-is-the-field-answer-and-it-leaks** — the dominant answer to the script's-own-directory problem is a first-class variable or core library, and each shipped one is caveated: Perl's is a once-only BEGIN block its own docs tell CPAN authors to avoid; PowerShell's was valid only in script modules until v3; CMake's has DYNAMIC scope, so inside a relocated definition it is the CALLER's directory, which forced a second variable. - **fnd-the-amalgamation-is-not-verbatim** — the flagship single-file counter-example is not concatenation. - **fnd-compile-to-fit-has-a-hard-ceiling** — the most aggressive shipped transformer states its own limits: string-mediated references are NEVER rewritten and so desynchronise from renamed ones; two separately compiled halves are mutually incompatible; every boundary must be declared as externs first. - **fnd-renaming-without-closure-degenerates-to-heuristics** — the most widely used JVM relocator rewrites SOURCE text by splitting on a word-boundary regex and then guessing, with two further regexes, whether each occurrence is a real reference. This is what the non-closed-set path actually looks like in production. [A-maven-shade-simplerelocator-2026]
- **fnd-loader-function-scope-leak-is-documented-in-bash** — a shipped bash tool ships the loader-function hazard and documents it: because sourcing happens inside its `load` function, `declare`d symbols never reach the caller. Independent corroboration of the floor manifest that refuted generated loader functions. [A-bats-writing-tests-2026]
- **fnd-directives-die-at-embedding-boundaries** — a comment-carried directive is unavailable wherever the script is generated rather than authored; the downstream project's only resolution was to disable the check by default. Prices the escape hatch Dorc has already welded out. [B-hadolint-sc1090-directive-2019]
- **fnd-entry-shaped-resolution-is-the-python-scar** — Python removed implicit relative imports because resolution was AMBIGUOUS and gave the relative form explicit syntax; the residue is that relative resolution keys off how the file was ENTERED, not where it sits on disk. Same shape as `$0` differing under `sh script.sh` / `./script.sh` / stdin, which the atlas measures. [A-pep-328-absolute-relative-imports-2004]
- **fnd-no-shell-prior-art-for-relocating-authored-sh** — the shell ecosystem reaches one-standalone-script by GENERATING from a non-sh config with per-command fragments merged in. If that generalises, 30P has no shell-native predecessor and must borrow from linkers and bundlers, which is what this note does. [C-bashly-readme-2026]

### The naming answer (remit item 4)

The industry does not have one word; it has three, and they cut at different joints.

- **layout / placement / mapping** — the linker's word for the phase that decides WHERE definitions go, parameterised by the user's own script. binutils: the linker script's main purpose is to "describe how the sections in the input files should be mapped into the output file, and to control the memory layout of the output file" [B-gnu-ld-linker-scripts-2026]. lld uses "orphan section **placement** rules" and "input sections have been **mapped** to output sections" [A-lld-linker-script-2026].
- **emission** — in the same toolchains this names writing the bytes out, downstream of every decision. It is the output step, not the decision step.
- **concatenation / scope hoisting / chunking**, with **bailout** for a named refusal — the bundler vocabulary for merging separately-authored units into one scope, renaming to keep it safe, and declining by named condition [A-webpack-module-concatenation-2026] [A-parcel-scope-hoisting-2024].

Read against that, "emission planner" is slightly off-centre: what 30P describes — a phase after analysis, parameterised only by the admin's requests, deciding placement and naming — is the field's **layout** or **placement**, and the component's closest first-party name is a **layout planner** or **placement planner**. "Emission" names the artefact-writing that follows it. Two honest counterweights: 30P's component genuinely owns both the decision and the form of the written artefact, so "emission" is not wrong so much as wider; and no linker term covers the naming half at all (that is "mangling" plus "symbol resolution"). A judgement for the human, not a defect.

## Where 30P is contradicted or under-enumerated

1. **`ask-dollar-zero-command-substitution-path` is a false dichotomy as written.** The plan offers
   two moves: recognise `$(dirname "$0")` and `$(cd "$(dirname "$0")" && pwd)` as fixed byte-shapes,
   or punt. The field supplies at least two more, neither of which models a command nor blesses a
   byte-shape: (a) strip one leading dynamic segment and resolve the literal tail against the book's
   own directory [A-shellcheck-checker-source-props-2026] [A-shellcheck-directive-wiki-2026]; (b)
   extract the literal bound and treat the operand as SET-valued over the snapshot, withholding when
   the set is plural — machinery 30P is already building for globs
   [A-webpack-dependency-management-2026] [A-vite-features-glob-dynamic-import-2026]. Option (a) is
   unsound in the general case and shellcheck can afford that; option (b) is exactly as sound as the
   glob ruling already is, and needs no allowlist, so
   `rul-small-allowlists-are-high-cost-minimal-count` never has to be invoked.

2. **`rul-no-tool-modelling-in-the-load-plane` forbids more than it needs to.** The rule is right that
   evaluating `dirname`'s output inside the engine is tool-modelling. But the shellcheck properties
   show that resolving *that exact idiom* does not require evaluating `dirname` at all
   [A-shellcheck-checker-source-props-2026]. The plan reads as though the rule forecloses the
   capability; it forecloses one implementation of it.

3. **The load principles are silent on a slashless operand.** POSIX resolves `. helpers.sh` (no
   slash) through PATH, not the cwd, and records that the cwd search was deliberately removed
   [A-posix-dot-builtin-2018]. `principle-load-operands-evaluate-over-controller-known-inputs`
   enumerates program text, `$0`, modelled cwd and the authored snapshot; PATH is none of those, and
   is a host-environment read the axis would exclude. This also touches
   `p-x-glob-load-no-match-aborts`: a no-match glob sources the literal pattern, and a literal
   pattern with no slash is a PATH lookup rather than an unconditional failure.

4. **`principle-book-code-source-is-inclusion`'s POSIX citation for positional parameters holds by
   silence, not by statement.** The dot page says nothing about positional parameters; what it does
   say is that operand-passing (`. f a b`) is a KornShell EXTENSION [A-posix-dot-builtin-2018]. "Keeps
   the positional parameters (POSIX)" is true because nothing sets them, which is weaker footing than
   the plan implies — and it makes the atlas's `. f a b` cell a conformance question, not merely a
   behaviour question.

5. **The `return` cell does not need the atlas to be decided in principle.** 30P calls it "the
   load-bearing measurement" and holds the exclusion set open until the mint. The standard already
   says the behaviour is UNSPECIFIED outside a function or dot script, with a named implementation
   split [A-posix-return-builtin-2018]. Measuring two shells can only report what those two do; it
   cannot make an unspecified construct specified. Keep the measurement; the RULING is available now.

6. **"Refuse the form" is a rarer posture than the plan acknowledges.** The nearest domain sibling hit
   the identical constraint — the payload must be pipeable into an interpreter's stdin — and answered
   it with a generated self-extracting wrapper rather than refusing
   [A-ansible-module-architecture-2026]. Dorc's floor manifest refutes that wrapper for sh on real
   grounds, corroborated independently [A-bats-writing-tests-2026], so the posture is defensible; but
   `rul-floor-is-uneven-across-forms` currently reads as though refusing is the obvious move, and the
   field's obvious move was the opposite. One sentence of self-awareness would strengthen it.

7. **Nothing found contradicts `kBACKFLIPS-verbatim-or-refuse` itself.** The counter-thesis was cast
   for as hard as the supporting material. Every strong compile-to-fit exhibit bought its success by
   constraining the *input*: a codebase written for the amalgamation and carrying its directives
   [A-sqlite-mksqlite3c-2026]; a whole-program closed world with declared externs
   [A-closure-advanced-compilation-2025]; an ES-module-only subset with an enumerated bailout list
   [A-webpack-module-concatenation-2026]. Dorc cannot constrain its input — the book is whatever the
   admin already wrote. The one genuine cost the weld imposes, which the counter-thesis does price,
   is that the refused set is discovered by the user rather than by the tool author; Chromium's
   thread is what that discovery feels like from the user's side [A-chromium-jumbo-removal-2019].

## Gaps and failures in this pass

- **Reddit is unreachable, by policy not by accident.** `https://www.reddit.com/robots.txt` is
  `User-agent: * / Disallow: /`; the fetch tool refused and no workaround was attempted. Item 3's
  community evidence therefore comes from issue trackers and a project mailing list, not forums.
  Kagi returns only snippets for reddit, and a snippet is not a source under this skill.
- **No peer-reviewed study of unity/jumbo builds was located** in this pass. The empirical content is
  the Chromium thread's own sampling — 254 CLs mentioning jumbo over six months, against the feature
  maintainer's counter-sample of ~10 in which 2 produced worse names [A-chromium-jumbo-removal-2019].
- **LLVM's `CodeGenerator.html` is deliberately NOT registered and NOT cited.** It is far too long to
  read in full here; its phase-7 "Code Emission" naming is therefore excluded from the item-4 answer
  rather than cited from a partial read.
- Not covered, and available on request: ELF `$ORIGIN` and `patchelf`; `-fno-semantic-interposition`
  and ODR/interposition; Ruby 1.9.2 removing `.` from `$LOAD_PATH` and adding `require_relative`;
  Node restoring `import.meta.dirname`; busybox's `.` operand handling; Lua `package.path`.
