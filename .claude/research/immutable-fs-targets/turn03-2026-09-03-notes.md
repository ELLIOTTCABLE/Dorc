## Findings (this turn; corpus-derived, pending turn01's evidence where marked)

  decline-with-hint, not a change to what is legal sh — the slap-on-top kind. It is also the
  cheapest containment of the login-shell residue: simple words survive zsh/fish/csh
  re-parsing identically.
- +SURE The emission-form floor is already uneven by ruling (`KNOBS:kBACKFLIPS`: "multipart
  accepts strictly more book code than single-stream"; `30P`: single-stream `.` lines are
  pasted or refused). An unwritable-fs host FORCES single-stream (no tree can land), so the

  paste/bundle is a strict improvement there, not a regression; the residue is the
  unpasteable exclusion set (`FORFEITS:forfeit-plain-sh-inclusion-analysis`; top-level

  core-language hole.
- +SURE The report lane's authored idiom is PATH-SHAPED by design
  (`printf '<verb> …\n' >>"${DREP_V1:-/dev/null}"`, `spike/CLAUDE.md:854-871`): the
  scaffold binds a file inside an exclusively-created scratch dir, drains it, frames it onto
  stdout. On an unwritable-fs host the scaffold binds `/dev/null` and every record is lost
  (disclosed). The IDIOM stays valid off-Dorc and on such a host (total by `:-/dev/null`),

  language one — the oracle author's line never changes.
- ~SUSPECT (pending turn01 H4) Here-documents are the one CORE-SH construct whose

- +SURE The records lane (`dorc-records/1` framed on the artifact's stdout, `262` §2) needs

## Proposed capability-granule division (proposal-tier; for the human to reshape)

Named so the "weird hosts" bucket stops being one bucket. Each granule is a per-host,
per-feature MEASURED capability under `kBOOT`'s matching rule, never a tier; a host sits in
several at once. G1 is the bulk; the rest are the frontier this round is mapping.

- **G1 `granule-floor-host`** — a floor-superset `sh` reachable over a duplex channel with
  file transfer, writable scratch, root or NOPASSWD sudo. `139` tier-A. Full product.
- **G2 `granule-unwritable-scratch`** — THIS ROUND. A floor `sh` present, no writable
  scratch at the controller-literal root (read-only root without tmpfs; hardened containers;
  ENOSPC/remount-ro failure states). Costs: single-stream only, in-memory delivery, no
  report records, no live topology, heredoc caveat under bash-as-sh. Two sub-cells worth
  keeping apart: STEADY (the host is like this by design — appliance) vs FAILED (it became
  like this — the moment the admin most needs the orchestrator).
- **G3 `granule-nearby-sh-executor`** (the human's second bucket) — a route to floor-sh
  execution exists but needs work first: (a) a floor-SUPERSET interpreter that is
  unmeasured against the dash∩posh weld (busybox ash on OpenWrt/Alpine/ESXi/Synology;
  bash-as-sh on RHEL/macOS; FreeBSD `sh`; mksh on Android; ksh as `sh` on some Unixes) — a
  DIALECT granule, cheap when the superset really is a superset; (b) `sh` present but not
  where the floor expects it (`/system/bin/sh`, no `/bin/sh` symlink) — a spelling granule;
  (c) sh must be BOOTSTRAPPED (Windows via a static busybox-w32 copied by the channel then
  invoked by path — `139` F-BOOTSTRAP) — one fixed native command, then G1/G2.
- **G4 `granule-no-shell`** — conceded: RouterOS, Cisco IOS/Junos CLI-only tiers, iDRAC/iLO
  restricted shells, Talos, printers/IoT. `139`: "a target that cannot evaluate any POSIX
  sh is unsupported". (Junos has a FreeBSD shell underneath; ~SUSPECT it is G3 not G4.)
- **G5 `granule-channel-class`** — `kBOOT`'s own axis, from the `ops-glue-residue`
  lane-survival table: DP+F (ssh with sftp/scp) · DP (docker/kubectl exec; dropbear
  without sftp — OpenWrt) · RR (SSM, Azure run-command, Proxmox guest-exec: payload inline
  in the request, hard in/out caps, no stdin) · OS (user-data, installer hooks: one-shot,
  no return path) · paste (serial console / human-mediated: echo, merged streams).
- **G6 `granule-privilege`** — root · NOPASSWD sudo · sudo-with-password (+ `requiretty`,
  which cannot coexist with a stdin payload) · non-root-only. `27C`'s dial.
- **G7 `granule-environment-minimalism`** — login shell parsing the remote command line
  (zsh/fish/csh); PATH minimalism (no coreutils beyond busybox; `printf` external under
  posh; `mktemp`/`timeout`/`cksum` presence and flag variance); `/proc` and `/dev/fd`
  presence; locale. Mostly containable in the remote command line's spelling
  (`sh -c '<posix>'`) and in stdlib oracles' argparse.
- **G8 `granule-resource-bounds`** — tiny flash (OpenWrt: writable overlay but wear; `/tmp`
  tmpfs fine), tiny RAM (an in-memory artifact of a few hundred KB is fine on 32 MB), RR
  channel caps (GCP 1024-char inline; AWS 64 KB in / 24 KB head-truncated out; Azure 4 KB
  tail), slow CPU.
- **G9 `granule-incarnation`** — reboots, kexec, first boot, re-image: `30W`'s index-kinds;
  out of this round.

The human's "nearby-sh-executor" is G3; "immutable-fs" is G2-STEADY; the unexpected
uncontrollable host is G2-FAILED. The bounding-box deliverable is: which real, frequently-
used hosts sit in G2/G3/G5-non-DP+F, and where the SIBLINGS strand them (Ansible's Python
precondition is the standing hypothesis for most of the stranding — front-2 to test).

## Return channels without a writable fs (sketch for a possible front; not gathered yet)

The only lane that needs a file today is DREP: the file is a per-site STAGING BUFFER so an
oracle's out-of-band `printf` lines can be framed with the site key AFTER the invocation
and put on stdout, separated from the tool's own stdout. Under ssh nothing but
stdin/stdout/stderr transits, so any "own channel" is ultimately multiplexed into one of
them on the remote side; the design question is only WHERE the framing happens.
- Option A (today): file staging, drain-then-frame. Needs writable scratch; degrades to
  `/dev/null`.
- Option B: a per-site pipe into a framer process, the sink named as `/dev/fd/3`
  (`exec 4>&1; { DREP_V1=/dev/fd/3 <invocation> 3>&1 1>&4; } | <framer>`). No fs write;
  costs one process per emitting site and `/dev/fd` presence (G7); keeps the authored
  idiom byte-identical.
- Option C: a second ssh session as the report channel — refused by
  `rul-repeated-probing-reviewed-before-design`'s posture unless reviewed; also `kBOOT`:
  DP channels have no second session at all.
- Option D: framed in-band by making `DREP_V1` a path whose writes are already framed —
  impossible without a process in the path (the oracle's `printf` cannot know the site key).
r14 already gathered the mechanism prior art (`notes/141`: apt `--status-fd`, bats fd 3,
pdsh's second connection, FIFO atomicity); a front here would gather only the NO-FS
variants (fd-sinks, `/dev/fd` portability, busybox `sh` fd handling) and is cheap.

## Glossary for the human (the obscure tools and terms cited so far; one line each)

- **rset** — Eric Radman's small OpenBSD-flavoured configuration tool: you write "plan"
  files of labelled shell snippets; it ssh's to each host and PIPES each snippet to the
  remote interpreter's stdin. Its author chose piping over copying so nothing is written to
  the managed host's disk (he distrusts managed hosts), then had to add a `-t` flag that
  copies-then-execs for snippets that need stdin or a tty — i.e. he hit exactly our hazard.
- **judo** — a tiny Go "ssh in and run these scripts" tool that scp's scripts to the host
  and runs them, and deliberately CLOSES fd 0 before running so any program that
  unexpectedly prompts fails at once instead of hanging.
- **drist** — Solène Rapenne's minimalist tool: rsync a directory tree to the host, then run
  one script. A maintained fork ships the one-connection "cat to a temp file, then exec it"
  shape that keeps stdin free — the shape the human's copy-then-exec lean resembles.
- **cdist** — a config-management tool whose "types" are shell scripts; copies via scp and
  runs "explorers" over ssh, one connection per explorer (slow); its manifests LOOK like sh
  but are not run as sh.
- **Mitogen** — an Ansible accelerator: bootstraps a Python interpreter on the remote from a
  400-byte command line, then runs everything in RAM over one ssh channel. The corpus's
  standing example of "no disk needed", bought by requiring Python.
- **Ansible pipelining** — sending the module code on the ssh command's stdin instead of
  copying it to the host first; faster; shipped OFF by default because `sudo` with
  `requiretty` needs a terminal, and a terminal and a stdin payload cannot coexist.
- **`requiretty`** — a sudoers option that refuses `sudo` unless a real terminal is attached.
- **tmpfs** — a RAM-backed filesystem; `/tmp` and `/run` are often tmpfs, so they stay
  writable when the disk is read-only or full.
- **overlayfs** — a writable layer stacked over a read-only base image; OpenWrt and the
  Raspberry Pi "overlay mode" use it so the base never changes.
- **`errors=remount-ro`** — an ext4 mount option (Debian's default): on a disk error the
  root filesystem flips to read-only rather than corrupting further.
- **`noexec`** — a mount option refusing to EXECUTE files from that filesystem; hardening
  guides put it on `/tmp`. `sh /tmp/file` still works, because the shell READS the file
  rather than exec'ing it; `/tmp/file` run directly does not.
- **`fs.protected_regular`** — a Linux hardening setting (4.19+) that stops root from
  CREATING or truncating files in a world-writable sticky directory (like `/tmp`) that
  another user owns; bites tools that write a temp file as one user and open it for writing
  as root.
- **`/dev/fd/N`** — a path that names an already-open file descriptor; on Linux it needs
  `/proc` mounted; on FreeBSD only 0–2 exist unless `fdescfs` is mounted.
- **ENOSPC** — the "no space left on device" error; a writable filesystem that cannot be
  written.

- +SURE The `/dev/fd` micro-granule is worse than turn03 guessed, on both sides: FreeBSD

  by the pipe inode's ownership — the man page's own example gets `Permission denied` as an
  unprivileged user ([A-linux-proc-pid-fd-manpage-devfd-2026]). For a DREP fd-sink: the
  artifact and its framer pipe are created by the ssh user, so same-user is fine, but under a

  someone else ⇒ denied. The naive Option B (turn03 §return channels) is dead unless probed
  AND privilege-checked; front-3's value drops accordingly.
