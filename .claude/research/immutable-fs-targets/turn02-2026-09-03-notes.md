## Findings

- +SURE The corpus's existing answer to "no writable fs" targets is the DEFERRED EXECUTOR
  corner: `142:Resolution` re-pinned `kCOMMS-executor-OOB` to {no-writable-fs, hard
  backpressure}, and `260` §0 fences r26 to "tier-A real-POSIX hosts with a writable
  `$TMPDIR`"; "busybox/no-fs/Windows targets ride the deferred executor corner". The
  in-memory slurp fallback is a far cheaper occupant of that same corner than a Mitogen-style
  RAM shim — same niche, no bootstrap.
- +SURE The r26 v1 wire was DELIBERATELY built to assume no remote scratch at all
  (`260:dec-26-wire-v1`: "zero new remote-fs assumptions"; §4: "v1 needs no remote scratch
  dir for the probe lane"). That is the "small cluster of early decisions" the human named.
  The as-built report lane (`DREP_V1`) does write to host disk, but under an explicit
  degrade-never-fail doctrine (`spike/CLAUDE.md` decline-class-emission; `render.rs:285`).
  So today's posture is: writable `/tmp` is OPPORTUNISTIC, never a precondition. The human's
  copy-default + slurp-fallback shape preserves exactly that posture; copy-then-exec WITHOUT
  the fallback would be the first hard writable-fs precondition in the transport.
- +SURE `KNOBS:kBOOT`'s floor triple {byte-clean stdin, separate stderr, non-echoing} is
  what the slurp fallback needs and nothing more; copy-then-exec adds "writable scratch" as a
  PER-HOST, PER-FEATURE capability — which is kBOOT's own prescribed resolution mechanism
  ("capability-probing per-feature, per-host … never a tiered degradation ladder"). A
  host-side, single-connection self-selection on the remote command line (`mkdir` exclusive
  ⇒ copy, else slurp) is capability MATCHING measured at delivery, not a ladder of assumed
  tiers — ~SUSPECT that reading survives the human's reading of kBOOT; worth a typed ack.
- +SURE Both alternatives hand every interior stdin-reader EOF (copy: `cat >f` drains the
  pipe before `sh f`; slurp: `$(cat)` drains it before `eval`). The stdin hazard is fixed
  IDENTICALLY by either. The two differ only in: where the bytes rest (disk vs memory), `$0`,
  `$LINENO`/error line numbers, whole-parse-before-run vs incremental, the spelling of a
  pre-execution integrity check, and cleanup residue. So "slurp is dangerous for the book"
  reduces to a short, lintable list, not a semantic fork.
- +SURE `sh -s` (today) executes as it reads, so a transport sever mid-stream RUNS A PREFIX of
  the artifact and the marker is lost (Unknown — safe by `rul-integrity-failure-withholds-
  mutation`, but the prefix already ran). Both alternatives hold the whole artifact before
  the first byte executes, so both admit a pre-execution integrity gate — the single-stream
  form would gain exactly what `30P:mech-two-standups` already demands of the multipart
  form ("every shipped file present and byte-matching its manifest; mismatch ⇒ stop before
  the first book line"). `cksum` (POSIX, busybox) against a controller-computed value is the
  cheapest spelling. -GUESS copy makes this trivial (`cksum <"$f"`); slurp needs the
  stripped-trailing-newline handled.
- +SURE The `$0` question is already carved by the load plane: `30P:model-symbolic-dollar-
  zero` (Dorc never reads `$0` from a shell; the analysis `$0` is the as-given book path with
  two live spellings) and `30P:rul-dorc-invokes-in-a-modelled-live-spelling` ("Dorc invokes
  what it ships in a spelling the analysis modelled as live (`sh ./plan.sh` from the
  generation root) … Single-stream (`$0` = `sh`) has no mirrored tree and its `.` lines are
  pasted or refused, so it is outside this"). Consequence: the MULTIPART form has assumed a
  materialized-on-host artifact all along (that is what `sh ./plan.sh` from a generation
  root means), and `tc-dollar-zero-is-script-anchored` (human-owned) proposes invoking the
  shipped plan BY ABSOLUTE PATH (`30Q` line 94). Copy-then-exec is the multipart form's
  transport with one file; slurp keeps single-stream's `$0`=`sh`. Neither is new territory
  for the load plane; single-stream's `.` lines are already pasted-or-refused, and the one
  open item ("whether single-stream should hint when `$0` is used outside a pasted `.`",
  `30P` line 471) becomes the lint the human's lean asks for.
- ~SUSPECT The delivery-shape choice is ssh/DP-class specific, not universal: every other
  channel class the corpus maps already materializes-then-execs FOR us (cloud user-data
  writes the payload to a file and runs it; RR channels carry the payload inline as the
  request with hard in-caps; Proxmox qga pairs `file-write` with `guest-exec`). The stdin
  pipe exists only because ssh offers stdin. Framing the amendment as "the ssh channel joins
  the materialize-then-exec norm, with an in-memory fallback where it cannot" is
  corpus-consistent (`ops-glue-residue` turn02's lane-survival table).
- +SURE `139` already leaned copy-then-exec for one target class for an unrelated reason:
  "Robust pattern = scp-then-invoke-by-path (the `sh -s` stdin-pipe is Win32-OpenSSH's buggy
  zone)". So the pipe shape has a second known enemy beyond stdin-eating.
- +SURE Engine-owned host writes have a settled discipline to reuse verbatim
  (`rul-probe-writes-only-what-it-owns`, `rul-scratch-root-never-read-from-host`, and the
  DREP precedent at `render.rs:285`/`:332`): controller-literal root `/tmp`, exclusive create
  by `mkdir -m 700 /tmp/dorc-<nonce>` (POSIX-atomic; sidesteps `mktemp`'s BSD/macOS
  template wart and, ~SUSPECT, `fs.protected_regular` since the file is not in the sticky
  dir itself), `rm -f` of the one file then `rmdir` (only-empty), never `rm -rf`, never
  retry by name, residue on crash disclosed not chased. Copy-then-exec fits that tier exactly
  (it is engine scaffolding on the command line, `rul-probe-mutation-ownership-split`'s owned
  tier). -GUESS the artifact file and the DREP scratch dir could share one exclusive dir, but
  they are created at different seats (transport command line vs artifact-side prologue) and
  the artifact must stay delivery-face-independent, so keep them separate at first.
- +SURE `law-artifact-floor` survives both shapes: the artifact bytes pass through `cat`
  untouched; the wrapper lives on the remote command line where the marker already lives
  (`marker.rs:78-82`). The change is one string in `SessionMarker::remote_command` plus the
  sim driver's wire expectation; the local driver runs the same string (`local.rs`), so the
  hermetic tier exercises the real shape (`260` §5 driver 2's ≥95% rule holds).
- ~SUSPECT A longer, control-flow-bearing remote command line raises an EXISTING latent
  hazard: sshd hands the command string to the user's LOGIN shell, so `if …; then`, `$(…)`,
  and `$?` are parsed by zsh/fish/csh before any `sh` runs (cdist's csh breakage is the
  corpus's recorded instance, `ops-glue-residue` turn02 lines 131-135). --WONDER whether
  today's `printf … "$?"` already misbehaves under fish (`$status`, not `$?`). The
  login-shell-agnostic spelling is to wrap the whole thing as `sh -c '<posix>'` so the login
  shell parses only a single-quoted string; a measurement for turn03, not a ruling.
- ~SUSPECT The lints the human's lean owes, from the corpus side: (a) a single-stream
  artifact whose bytes read `$0` (the `30P` open hint); (b) a book/oracle line that reads
  stdin with no redirect (today it eats the artifact; after the amendment it sees EOF —
  still worth a lint, `26Lb` already names `read` in a shipped book as lint material under
  `rul-interactivity-is-local-books`); (c) PENDING turn01's H4: if bash-as-sh needs a temp
  file for here-documents, then on a no-writable-fs host under slurp any artifact with a
  heredoc fails at that line — a lint keyed on (host has no writable scratch × artifact
  contains a here-document × remote `sh` is bash), disclosed at plan time from the probe's
  own delivery mode.
- +SURE The three-faces rule (`26K:concl-offline-compile-is-a-face-not-a-product`: "narrowing
  allowed, semantic forks never") is not breached by EOF-on-stdin — the paste face
  (`ssh host sh <plan.sh`) has the same hazard and the same EOF behaviour once a human
  drains the pipe. The only face-visible difference either alternative introduces is `$0`
  (paste: `sh`; copy: a temp path), already contained by single-stream's paste-or-refuse
  rule for `.` lines and lintable elsewhere.
- +SURE Which documents the amendment touches, if ruled: `260` §5 (the invocation line and
  driver 2); `KNOBS:kBOOT` (the floor statement gains "writable scratch is a probed
  per-host capability selecting the delivery shape"); `spike/CLAUDE.md` (one delivery-shape
  bullet under host evidence; the `$0` note); `ANALYZER-NEEDS:an-host-capability-handshake`
  (a delivery-mode fact); `AID-NEEDS` (one row: delivery-fallback disclosure + the heredoc
  lint); the marker grammar gains a `mode=` key on the marker line so the controller learns
  which shape ran (transport framing, extensible by the records-lane additive-keys policy).
  `FORFEITS` is untouched (this is not an analysis limitation).
- ~SUSPECT Velocity: the transport change is small (one function, its tests, the sim/e2e
  transcripts that carry the remote command line). The cost that could kill velocity is not
  the mechanism but deciding the fallback's SELECTION and DISCLOSURE (host-side self-select
  in one connection vs a capability handshake round-trip — the former is the one consistent
  with `rul-repeated-probing-reviewed-before-design`, which forbids a second exchange
  without review) and authoring the lints' prose (human-tier per
  `error-authorship-tier`).
