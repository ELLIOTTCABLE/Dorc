## Agent-H digest (CM-tool shell escape-hatches) — landed, curated

- repurp-finding73 +SURE (ops-hyp1 CONFIRMED, all four tools): every CM tool's shell
  escape-hatch defaults to ALWAYS-CHANGED and demands hand annotations — Ansible
  creates/removes/changed_when (+ the no-changed-when / command-instead-of-* lint trio,
  verbatim rationales); Puppet creates/unless/onlyif (+ the documented creates-never-
  created infinite-rerun trap); Chef not_if/only_if/creates + the guard_interpreter and
  guard-env-inheritance traps; Salt onlyif/unless/creates. willthames (ansible-lint
  author): "Ansible has no mechanism for understanding whether your command changed
  anything." Puppet's own docs: complex exec piles → "develop a custom resource type
  instead" — their graduation path is LEAVE shell; ours is DESCRIBE it.
- repurp-finding74 +SURE (ops-hyp2 SHARPENED — the round's sharpest finding): incumbent
  dry-run on shell content is TRI-MODAL and broken in all three modes — Ansible --check
  SKIPS shell/command/script entirely ("modules that do not support check mode report
  nothing and do nothing"; #84676 maintainer-confirmed); Puppet noop and Salt test=True
  RUN GUARDS FOR REAL (side effects at agent privilege during a "dry" run — documented
  hazard); Chef why-run is vendor-disowned ("considered harmful"; can't forecast guards
  depending on earlier resources; the nightly-why-run-broke-prod systemd story). Root
  cause common to all: NO mechanism distinguishes a safe check from an unsafe one — which
  is exactly what the authored vouch provides. Our probe phase (kFAIL-withhold: only
  vouched-read-only checks ship) threads the needle none of them can: a dry-run that is
  genuinely dry AND genuinely informative. This is THE positioning sentence for ops.
- repurp-finding75 +SURE: Chef's why-run post-mortem generalizes the staleness problem in
  vendor prose ("Something that runs earlier … can modify the system so that later
  resources can observe a different state" — explicitly extended to Puppet and Ansible) =
  the poison-wall/frame problem, independently stated by an incumbent as the reason
  dry-run is impossible for them. External validation of the walls design from the
  category's own literature.
- repurp-finding76 +SURE: Salt got CLOSEST to an oracle contract — the `stateful: True`
  protocol (script self-reports changes via last-line key=value/JSON on stdout) plus
  `test_name` (author supplies a SEPARATE command to run under test=True that forecasts
  changes) = a hand-authored predict/is_converged analog, in-band on stdout. Prior-art
  convergence for the role-sibling family; also a warning: their channel is stdout's last
  line (collides with byte-faithful passthrough — see finding78).
- repurp-finding77 +SURE (happy-child intel): Ansible `script` pushes a local file and
  executes via the remote shell WITHOUT Python (shebang honored absent `executable:`) —
  a dorc-run script rides it; caveat: ssh connection forces `-tt` for scripts ⇒ stderr
  MERGES into stdout (transparency hazard for the embedded contract). `raw` has no change
  handler and never checks. Structured-output seams exist in all four (ansible.posix.json
  callback; Puppet YAML/http report processor; Chef Data Collector JSON; salt --out=json)
  — sibling-consumption of THEIR runs is viable.
- repurp-finding78 ~SUSPECT (new design tension, flag): a Dorc-embedded script could
  self-report ACCURATE changed-ness to its host tool (fixing the always-changed problem
  mechanically): Salt's stateful last-line protocol is the blessed channel; Ansible via
  changed_when over registered output. But those channels live ON STDOUT — in tension
  with R2 byte-faithful passthrough. Resolution shape: per-host-tool opt-in adapters
  (author chooses; the host tool DEFINES the stdout convention, so emitting it is
  conforming, not polluting). Cheap-add candidate: "changed-report adapters," smallest
  possible per-tool shims.
