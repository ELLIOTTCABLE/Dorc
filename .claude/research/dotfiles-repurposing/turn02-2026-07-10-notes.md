## Findings (main-context analysis half, pre-gatherers)

- repurp-finding44 +SURE (in-corpus, 24Q + 24P §9): the slot-in skeleton ALREADY EXISTS —
  `dorc-sh` (spike-minimal strip-and-exec shebang runner, $0/"$@"-faithful, executor
  bandwidth reserved via `--`, shebang never parsed by anything). The minimal-glue vector
  for "Dorc inside a host tool" is the script's OWN line 1; the host needs zero awareness.
  Missing between strip-and-exec and fixing scripts-pain: an ANALYZED local runner behind
  the same seam (probe → elide/guard → exec).
- repurp-finding45 (framework): three composition directions —
  A. Dorc-below (Dorc runs the scripts a host tool owns: chezmoi run_, yadm bootstrap,
     home-manager activation, devcontainer lifecycle, mise tasks, git hooks, make/CI);
  B. Dorc-above (a Dorc book orchestrates host tools as lines: `chezmoi apply`,
     `brew bundle`, guarded by oracles DELEGATING to native check verbs);
  C. side-by-side (no integration; Dorc's statelessness + non-ownership of files means no
     fight when the host mutates the world — contrast home-manager's ownership fights,
     ayats). All three compose; A is the "live forever in the niche" shape.
- repurp-finding46 +SURE: direction-A's value in the chezmoi slot: run_once_/run_onchange_
  are STATE-memory rationing hacks (run scripts rarely because they're expensive/unsafe);
  Dorc dissolves the rationing — mark everything run-always, elision makes it cheap,
  guards make it safe, probes catch host-drift that content-hash memory structurally
  misses. Host tools have zero insight into script interiors (verify/diff are file-level);
  Dorc's plan/why gives the interior report. (Gatherer verifying the state-semantics
  details.)
- repurp-finding47 (the direction-A requirements contract — glue-pain minimization):
  R1 local-exec mode (finding2, upgraded to HARD prerequisite);
  R2 embedded-transparency: stdout/stderr byte-faithful passthrough, rc identical to bare
     sh (hosts abort on nonzero); ALL Dorc signalling OOB — kCOMMS-executorless-OOB
     discipline applied locally. Cheap to bless now, retrofit-painful later;
  R3 headless consent: no plan-ack inside a host's apply (sanctioned: bare `dorc apply` =
     no-worse-than-blind); the attention product RELOCATES to the after-the-fact plan
     artifact/why-log — consonant with the attention-chronology doctrine (23D §4): in
     embedded mode there is no right-after-return epoch at all;
  R4 latency: analysis sits in the host's interactive hot path (finding8 upgraded —
     always user-perceptible locally);
  R5 env-var facts (CHEZMOI_OS et al.) = read-value lane rider (finding3 family);
  R6 rendered-input tolerance: .tmpl scripts analyze at exec-time only (post-render);
     authoring-time analysis needs un-templated books — Dorc rewards sh-branching instead,
     no engine change, docs note;
  R7 NO second state DB (kSTATE-parked is load-bearing FOR composition: zero state
     collisions with the host's own script-state memory; nothing keyed on script hash, so
     per-apply re-renders don't confuse us).

## Agent-E digest (chezmoi scripts deep-dive) — landed, curated

- repurp-finding52 +SURE: chezmoi renders (.tmpl) → temp file → chmod 0700 → DIRECT exec:
  shebang honored, no implicit sh (source-confirmed, realsystem.go). ⇒ dorc-sh vector works
  per-file with ZERO chezmoi config. Second vector: `interpreters.sh = {command = …}`
  remaps EVERY .sh script through a custom command (config-level, whole-corpus). Two
  graduated adoption levels, both existing first-party seams, no partnership needed.
- repurp-finding53 +SURE: script state written ONLY on rc 0 (source-confirmed,
  targetstateentry.go); run_once_ keyed by content-SHA, run_onchange_ by target-path SHA
  (two buckets); apply is fail-fast by default (-k opts out). ⇒ R2 transparency (rc/cwd/
  stdout fidelity) is exactly what preserves host semantics; Dorc statelessness = zero
  interference with either bucket (R7 confirmed hard). CWD contract (script's dest-tree
  location; before_-scripts walk up) adds cwd-fidelity to R2.
- repurp-finding54 +SURE (confirms finding48 with verbatim): the effect-preview slot inside
  chezmoi is EMPTY BY DESIGN — diff shows script TEXT, `apply --dry-run` does NOT execute
  scripts, "All scripts should be idempotent … should be used sparingly" (maintainer
  doctrine), package-install admitted "fundamentally imperative". The answer to "what will
  this script do?" is "here's the shell source." Dorc's plan is precisely the missing
  artifact, and the incumbent's doctrine prevents it from building one.
- repurp-finding55 +SURE: the canonical composition idiom (.chezmoidata packages +
  run_onchange_ + embedded brew-bundle heredoc; "no more five-minute brew install cycles")
  is a drift-BLIND trigger: host drift under unchanged content never re-runs (uninstalled
  formula stays gone until someone edits the LIST). Dorc-inside converts content-memory to
  reality-probing — strictly better on the exact axis the idiom exists to serve. The
  concrete demo story for direction-A.
- repurp-finding56 ~SUSPECT (direction-B rider): a chezmoi oracle by delegation
  (`chezmoi verify` rc) has one open semantic: verify/status with always-run_ scripts
  present may report perpetually-unconverged (agent could not pin the exit-code matrix from
  source). Oracle likely needs `status.exclude=["scripts"]` guidance or an answer-2 decline
  when scripts pending. VERIFY BEFORE P5 writes it.
- repurp-finding57 +SURE: hooks = whole-apply bracket seam (apply.pre/.post; run even under
  --dry-run; "should be fast and idempotent"); no per-script hook exists ⇒ shebang +
  interpreters stay the per-script vectors (confirms finding51: prefer the host-agnostic
  seam). Script papercuts verified for the value story: no single-script re-run lever
  (bucket-nuke folklore, maintainer-confirmed), lexical-only ordering (no dep graph),
  scripts hidden-from-diff demand.

- repurp-finding59 +SURE (finding48 upgraded chezmoi→ecosystem-wide): the
  idempotence-contract-without-tooling pattern is first-party-verbatim in FOUR tools —
  yadm "best to make the logic of your bootstrap idempotent"; dotbot "bootstrap
  configurations should be idempotent"; home-manager "Any entry here should be idempotent";
  chezmoi "All scripts should be idempotent." The entire ecosystem's script slots carry
  exactly the contract Dorc mechanizes, and none of them help the author meet it.
- repurp-finding60 +SURE: home-manager's activation protocol (read-only checks before

  cannot reach. Positioning line: Dorc derives what home-manager's contract demands you
  hand-write.
- repurp-finding61 +SURE: `brew bundle check || brew bundle install` is FIRST-PARTY-BLESSED

  idioms are already the check-then-execute shape Half-B lifts. Oracle-authoring caveat
  bank: Brewfile is RUBY — `system` guards execute even during `brew bundle check` (the

  check's rc differs under --verbose (#401); `git status --porcelain` signals via EMPTY
  STDOUT not exit code; `stow -n` has no clean boolean (parse output); mise/devbox/
  topgrade ship NO convergence verb. Pattern: declarative tools ship booleans, imperative
  runners ship nothing — Dorc is the bridge.
- repurp-finding62 ~SUSPECT (finding46/55 generalized): re-run-semantics confusion is a
  cross-ecosystem pain CLASS — chezmoi run_once_ reset folklore, devcontainer
  postCreateCommand once-only surprise (#1153), devbox's own docs steering mutating work
