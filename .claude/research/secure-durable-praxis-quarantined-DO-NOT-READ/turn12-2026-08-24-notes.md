# turn 12 — 2026-08-24 03:11:47 CDT

Front: can one directly readable, deliberately tiny grammar carry the durable
whylog without intolerable parser or cryptographic glue? Worked from the acked
policy direction only; the earlier round in this directory was not read.

## Findings

- The decisive question is not text-vs-binary. It is whether the thing bound by the MAC is *the literal file bytes* or *a re-derived model*. Every failure found here — SOPS, OpenPGP clearsigning, JCS/Canonical-JSON, PEM — is a re-derivation failure, and re-derivation is equally available to binary formats.
- The closest shipped analogue of the artifact's rich projection is SOPS, and it binds the wrong thing: key *paths* as AEAD associated data plus a MAC over reconstructed *values*, not over the file. It has a live, deterministic bug where a file `sops -e` just wrote cannot be read by `sops -d`.
- age is the counter-example that works: an ASCII line-framed header carrying opaque-value-capable material, MACed over the literal header bytes through the `---` marker, no canonicalization step anywhere in the verify path.
- Canonicity is relative to a chosen equality relation. If the durable's equality *is* byte equality — which is what content digests, `diff`, and quoting already assume — then the canonicalization obligation is discharged trivially and the whole JCS/dCBOR machinery is answered by not needing it.
- Length-prefix framing does not buy allocation safety for a whole-file local artifact; it buys a trust-the-attacker's-number hazard. The mature-binary-parser CVEs are exactly this, and their fixes are "allocate proportional to input actually present" — which a bounded scan has by construction.
- Text-format parser differentials in the wild trace overwhelmingly to *tolerance rules*, not to textness: 105 of 180 effective MIME bypasses were implementations not following the spec, 75 were the RFC declining to define abnormal-input handling. A greenfield strict grammar has neither category.
- A readable durable adds a parser that binary does not: the human. That is a documented differential category with real exploits, and it is the one genuine security cost of the thesis that cannot be engineered away, only bounded.
- RFC 7468 is the strongest standards-level statement of the binary counter-thesis ("if canonical encodings are desired ... decode into DER") and simultaneously contains its own rebuttal: its ambiguity is retro-fitted permissiveness, and its own Figure 3 strict grammar is unambiguous.
- The binary counter-thesis's real asset is not determinism but *verified parsers*: EverCBOR/EverCDDL emit formally-verified non-malleable Rust. Its price, for this project specifically, is that those components are marked unavailable on Windows.
- Prototype (built, compiled, 6/6 tests green): an age-shaped readable grammar with a running-transcript AEAD binding gives byte-identical round-trip, refuses every non-canonical mutation tried, catches every single-byte mutation at every offset, reports a monotone verified-prefix under truncation at all 515 cut points, and survives `grep`/`diff`/`less` intact.
- The plain projection needs no runtime enforcement: a Rust enum without an `Opaque` variant makes "cannot represent the withheld field" a compile-time property, and the narrowing function is total.
- Opaque bytes never need to appear raw on disk. Ciphertext is already opaque, so base64 costs nothing; the raw-byte escape hatch is only needed for the *disclosed-cleartext* policy, and even there base64 is preferable because raw bytes let authored content impersonate the grammar's own framing to the human reader.

## Prototype record

Built in scratch (`dwl`, edition 2024, `unsafe_code = "forbid"`, deps: base64,
chacha20poly1305, hkdf, hmac, sha2). Compiled under rustc 1.96.0; six tests
green. What it actually ran, as distinct from what was inferred:

- `round_trip_is_byte_identical_and_content_exact` — model → bytes → model →
  bytes is byte-identical, and the model survives exactly, including an opaque
  member containing NUL, CR, invalid UTF-8, and a line reading
  `--- AAAA` followed by `   disposition = elide` (i.e. content impersonating
  the grammar's own framing and its closing marker).
- `every_single_byte_mutation_is_caught` — for all 515 offsets × 2 deltas, no
  mutant verified.
- `truncation_reports_what_is_still_true` — 467 of 515 cuts returned a
  `Truncated` report; none parsed as whole; the proved-authentic prefix rose
  monotonically to 441 bytes as more of the file arrived.
- `declared_length_never_drives_allocation` — a header claiming a 1 000 000-byte
  body in a 47-byte file is refused against bytes present.
- `non_canonical_forms_are_refused` — CRLF, tab indent, two-space indent, a
  trailing byte after the closing line, and a doubled sigil space are each
  rejected with a distinct typed error.
- `plain_projection_cannot_carry_opaque_members` — the narrowing is a total
  function into a type with no opaque variant; the rendered plain document
  contains `argv = withheld` and no sealed or disclosed member.
- Ordinary tools, run against the sealed rich sample: `grep -n disposition`
  returns two clean hits with line numbers; `grep -cE '^ *[a-z-]+ ! [0-9]+$'`
  counts sealed members; `diff -u` produces a one-line hunk with readable
  context for a one-field change; `less` pages it as ordinary text.

Not built, not measured, and therefore not claimed: performance, fuzzing,
concurrent readers, any second implementation (so nothing here bears on parser
equivalence in practice), and the csexp comparison candidate.

## Weak points I am aware of in my own reasoning

- The prototype is one implementation written by the same agent that wrote the
  grammar. It shows the grammar *can* be implemented with these properties; it
  says nothing about whether two independent implementations would agree.
- The human-as-parser risk is argued from [A-ali-smith-parser-differential-antipatterns-2023]
  and [A-gpgfail-notdashescaped-forgery-2025] but not measured; no user study
  exists here and none is cheap.
- I did not find a shipped precedent for a *nested* readable grammar with a
  whole-file MAC. age is flat; SOPS is nested but binds a re-derived tree.
  The construction proposed is a composition of two proven pieces, not a
  proven whole.
